# Решение № 14 — script-state-flow

Родитель — № 12. № 13 принадлежит параллельной работе другого чата и не изменялся. Добавлен перенос ответов между обработчиками через объявленные переменные классического JavaScript-скрипта с проверкой области видимости и принадлежности странице.

{{METRICS}}

S0 и весь submission.json S0–S7 совпадают с № 12. Изменение проверено на независимых исходных примерах; сокращения неизвестных входов Train Ticket в этой версии нет. Remote=1 в S0 означает совпадение пустых множеств. Скрытые сценарии сайта не оценивались. Все сценарии partial, цель устранить все неизвестные входы не достигнута.

## Что изменилось

- Ответ HTTP сохраняется в переменную только при доказанном связывании с единственным объявлением var в области скрипта. Параметры, локальные и блочные переменные, catch, функции и лексические тени не получают чужое значение. Разбор переиспользует исходное AST; имена проекта не прописаны в ядре.
- Начальное значение берётся из безопасного литерального префикса. Следующая наблюдённая success-функция может его заменить; неизвестное условие записи делает значение неизвестным. Хранилище разделено по страницам и сценариям. Утраченная страница не получает заново известное начальное значение при позднем обращении к другой переменной.
- HTTP-ответ копируется на границе браузера: позднее изменение серверного объекта не меняет уже полученные клиентом данные.
- Записи вне наблюдённого callback, циклы, ранний выход, вызовы с неизвестными эффектами, алиасы, динамический this и неоднозначное подключение скриптов не дают подтверждённых значений. Причины отражаются в диагностике. Предупреждения относятся к востребованным переменным и не загрязняют независимые Vue-поля.
- Исправлена потеря чистых связей Vue из-за комментариев между методами. Неподдержанные объявления компонентов, включая mounted в кратком синтаксисе, обозначены явно; их выполнение не выдумывается.

Модель намеренно узкая: один однозначный классический скрипт в одной доказанной HTML-странице, локальные известные подключения, закрытые литералы и простые записи из наблюдённых ответов. Произвольные события, таймеры, модули и полный JavaScript не исполняются. Общие ограничения Java/Spring/ORM/JSON и языкового выбора запросов остаются. Подробности — в [DIAGNOSTICS.md](DIAGNOSTICS.md).

Все исправления ревью № 10 унаследованы из № 11 и проверяются сохранёнными регрессиями: HTTP-глагол; гарантированные отказы, фильтры и HTTP-ошибки; switch/catch; UUID; единицы и форматирование; MySQL; заголовок и описание сценария; Profile, int и каталог sample. Поддержка fetch/axios и Vue SFC по-прежнему отсутствует и диагностируется.

## Воспроизведение

Из каталога варианта:

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py --source ../../tt-challenge/targets/trainticket --skeleton ../../tt-challenge/skeleton/trainticket.json.gz --context ../../tt-challenge/context --scenarios ../../tt-challenge/scenarios --output /tmp/solution14-reproduced.json --report /tmp/solution14-report.json
PYTHONPATH=code .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
~~~

Для другого проекта заменяются входы. Граф-скелет обязателен. Анализатор работает на Python без моделей и сетевых API, исследуемое приложение не запускает. Установка пакетов требует их доступности. [Offline-аудит](benchmark/analysis-report-offline-audit.json), [изолированный CLI с каталогом sample](benchmark/standalone-sample-input.json), [проверка оснований рёбер](benchmark/verification.json), [повтор с другим ID/hash seed](benchmark/reproducibility.json).

## Проверки и пределы вывода

Новая синтетическая цепочка catalog → script var → checkout → HTTP другого сервиса → таблица проверяет вручную перечисленный полный граф всех четырёх отношений для двух состояний данных. Она не доказывает переносимость на реальное приложение. На 78 реальных Java-файлах Petclinic REST v2.1.5 повторены [11 проверок выбора](benchmark/petclinic.json) и [графы ограниченных тел GET → PUT → GET](benchmark/petclinic-body-graph.json): executes/calls/data IoU=1, изменение состояния сохраняется. Полный HTTP/security/validation/Jackson-граф не проверен, remote в Petclinic пуст. Универсальность не заявляется.

[Аудит входов](benchmark/input-coverage.json) сохраняет оставшиеся 18 шагов и 40 пар шаг–поле; ни один пропуск не спрятан переименованием или свободным символом. Есть как недостающие пользовательские данные, так и технические ограничения. [Свидетель неоднозначности](checks/missing-input-witness.json) доказывает нехватку двух новых значений, но не объясняет все пропуски.
