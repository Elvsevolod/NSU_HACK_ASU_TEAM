# Границы варианта № 17

Правила относятся к Java/Spring и нативным коллекциям; бизнес-имён, готовых маршрутов и идентификаторов сценариев в новых правилах нет. Предыдущие ограничения JSON, Spring и языкового выбора запросов сохраняются.

## Проверенная область

keySet/values/entrySet хранят ссылку на исходную Map. Последующие put, remove и clear видны существующему представлению; поддерживаемые изменения через представление меняют карту. Проверены contains/remove, размер, очистка, iterator/next/remove, getKey/getValue/setValue. Служебные классы создаются только адаптером: поля пользовательского JSON не превращают объект в представление Map.

String/Character и Integer/Long различаются при поддерживаемом сравнении значений. Сведения о boxed-классе сохраняются при копировании, putAll и поддерживаемом HTTP generic-binding. Число Python в Object не доказывает класс Integer. Floating boxing, пользовательские equals/hashCode и все реализации Collection не воспроизводятся полностью.

Порядок HashMap не подменяется порядком словаря Python. Наблюдаемый выбор элемента моделируется альтернативами и предупреждением. У обычного LinkedHashMap учитывается доказанный порядок вставки; копирование из неупорядоченной карты не создаёт доказанного порядка. При исчерпании бюджета обхода/альтернатив неопределённость сохраняется, изменяемые значения расширяются, возможные связи добавляются приближённо. Точный порядок конкретной JVM не предсказывается.

Известные ошибки iterator.next/remove прекращают выполнение в поддерживаемой однопоточной модели. Неопределённая модификация получает диагностику. Поведение Map.Entry после других изменений карты не объявляется определённым. Ссылочная идентичность разных фабричных представлений/итераторов остаётся неизвестной, если её нельзя доказать.

Сокращение большого for-each применяется только к единственному действию dst.put(k, source.get(k)), с нативными изменяемыми картами, доказанными непересекающимися ключами без преобразований и без дополнительных эффектов. Ранний break/return, общий целевой ключ, чтение изменяемого результата и сложное вычисление не подходят под это доказательство. Содержимое копируется без перебора перестановок; порядок новых ключей LinkedHashMap остаётся неизвестным, если исходный порядок неизвестен.

При консервативном объединении ветвей сохраняются доказанные aliases и согласованные записи в исходных объектах вызывающего метода. Условное совпадение ссылок расширяется, включая поля исходного объекта, исключённые из JSON. Копирование состояния представления сохраняет связь только с копией backing Map.

## Сохраняющиеся ограничения

- Stream над представлениями Map и неподдержанные операции, например spliterator, явно диагностируются. Наличие stream для ограниченных List из родителя не означает поддержку всех Collection. В панели отдельно измерен пропущенный callback: точного графа здесь пока нет.
- Прямое generic-чтение из Entry/Iterator при несовпадении доказанного boxed-класса с объявленным типом возвращает неопределённость с предупреждением. Полное место и тип неявного Java checkcast не моделируются. For-each имеет отдельную проверку поддерживаемого преобразования до тела. Полная подстановка generics, wildcard и произвольный overload resolution остаются открытыми.
- В HTTP/JSON пустые и упорядоченные представления ключей/значений передаются массивом. Неизвестный наблюдаемый порядок оставляет неопределённый массив. Схема сериализации Map.Entry зависит от codec, версии и аннотаций; без доказанного адаптера она неизвестна. Циклы в поддерживаемой проекции диагностируются как ошибка сериализации. Полный Jackson/JavaBeans не заявляется.
- Объединение неизвестной длины обычных Python-списков, сложные циклические кучи, equals с исходными callback и произвольные JVM/SDK-конструкции требуют дальнейшей модели. Новые правила не превращают ядро в полную JVM.
- Полный жизненный цикл Spring, регистрация beans, фильтры, безопасность, валидация, codecs и обработчики исключений покрыты частично. Языковой выбор API сохраняет эвристики. Полного эталонного HTTP-графа независимого реального приложения пока нет.

## Значение измерений

В основной завершённой проверке все восемь сценариев partial. Неизвестные входы — 46/103 шага, 137 пар шаг–поле; эти показатели считают все альтернативы. Частоты operation_issue_steps показывают повторное распространение ограничений, а не точность отношений или число независимых дефектов. Отчёт для построения ответа не читался.

38 компонентов панели имеют вручную заданные до предсказания ссылки: 36 графов совпали, два остались неполными. Это подборка механизмов, не случайная выборка проектов. Непустые executes/calls/remote/data проверяются отдельно, пустое отношение считается непроверенным. Petclinic проверяет прежнюю ограниченную цепочку тел методов, без полного HTTP/security/Jackson-графа. Свидетель отсутствующих значений объясняет две неоднозначности данных, а не оставшиеся технические пропуски.

Контракты сверены через Context7 и первичные источники: [HashMap](https://docs.oracle.com/javase/8/docs/api/java/util/HashMap.html), [LinkedHashMap](https://docs.oracle.com/javase/8/docs/api/java/util/LinkedHashMap.html), [Iterator](https://docs.oracle.com/javase/8/docs/api/java/util/Iterator.html), [StreamSupport](https://docs.oracle.com/javase/8/docs/api/java/util/stream/StreamSupport.html). Различия сериализации Entry подтверждает [обсуждение разработчиков Jackson](https://github.com/FasterXML/jackson-databind/issues/865). Эти источники и внешние модели не используются при построении ответа.
