# Границы варианта № 16

№ 16 продолжает № 15 и сохраняет его ограничения HTTP, JSON, ORM, браузера и жизненного цикла Spring. Новые правила относятся к семантике Java; названия исследуемых сервисов, бизнес-полей и сценариев в них не используются.

## Что проверено

- Тип выражения сохраняется для поддерживаемых сравнений, логических операций, строковой конкатенации и ограниченного числового conditional. Ключи Map различают String/Character и Integer/Long/Byte/Short/Boolean. Форма значения Python сама по себе не доказывает класс Java.
- Символ Java декодируется до участия в числовом продвижении. Поддержаны обычные литералы и проверенные escape-последовательности; повторные Unicode-преобразования всего Java-файла не реализованы. Длина char определяется единицей UTF-16.
- Локальные переменные блока, for, for-each и catch прекращают перекрывать внешнее имя после выхода из области, в том числе при return/throw/break/continue. Изменения внешних локальных переменных и объектов при этом сохраняются.
- Объявленные типы for-each и явных параметров лямбд доходят до тела. Для неявных параметров ограниченного последовательного stream используются простые контракты List<T>/ArrayList<T>/LinkedList<T> и однородного Arrays.asList. Тип после map выводится только из согласованных исходных return-типов, без выполнения callback во время вывода типа. Вложенные и wildcard generics, сложное наследование и неоднородные результаты остаются границей поддержки. Параметры типов, в том числе с именами String/Integer, учитываются в своей области и не принимаются за одноимённые классы JDK. Если точная подстановка неизвестна, тип ключа остаётся неизвестным; пример этой границы включён в панель отдельно.
- Тип возвращаемого исходного метода разрешается в пространстве имён его объявления. При доступном типе receiver учитываются исходные методы и их сигнатуры. Это не полная реализация Java overload resolution или компилятора.
- Распаковка известного null в примитив прекращает поддерживаемое вычисление с NullPointerException: условия, арифметика, присваивания, cast, update, возврат и однозначные исходные параметры вызова. Следующий операнд/аргумент не выполняется после такого отказа. Конкатенация строки с null, сравнение ссылок и короткое замыкание не требуют лишней распаковки. Нативные SDK-перегрузки не охватываются автоматически этим правилом. Неопределённая распаковка generic-типа оставляет предупреждение и возможные пути; точное исключение в этом случае не заявляется.
- Доказательства стандартных типов кешируются только по неизменяемому исходному проекту и пространству имён. Значения, состояние сценария и локальные привязки в этом кеше отсутствуют. Проверка оснований рёбер повторно использует множество рёбер альтернативы вместо его построения для каждого основания; критерии проверки сохранены.

## Что остаётся открытым

Объект с объявленным типом Object/Number не всегда имеет доказанный конкретный boxed-класс. Он остаётся неизвестным ключом Map, даже если Python хранит конкретную цифру. Межветвевые совпадения значений не подменяют доказательство их типа.

Представления keySet/values/entrySet и их обход требуют модели связи с исходной картой, alias-мутаций и порядка. Они не заменены снимком Python-списка. Неподдержанный обход этих представлений возвращает неизвестное значение с предупреждением. Семантика всех Java Collections, фиксированных и неизменяемых списков, native SDK и JVM не заявляется полной.

HTTP/JSON по-прежнему использует ограниченную проекцию полей. Она не воспроизводит все конструкторы, JavaBeans, codecs, bean registration, security, validation и exception resolvers. Языковой выбор API и часть браузерных эффектов остаются эвристическими. Полный HTTP-граф независимого реального приложения не измерен; проверка тел Petclinic ограничена заданными предусловиями.

## Как читать результаты

Панель checks/check_mechanisms_v11.py состоит из небольших компонентов с вручную зафиксированными до запуска эталонами. Она локализует дефект механизма и проверяет четыре типа связей там, где отношение непустое. Это диагностическая подборка, а не оценка переносимости на случайной выборке проектов.

Частоты operation_issue_steps в benchmark/coverage-summary.json показывают охват ограничений, не precision/recall. Одна потеря значения распространяется на следующие операции. Исправление раннего типа может открыть ранее недоступную неподдержанную операцию.

Счётчик входов берётся из явных Unknown input по всем альтернативам завершённого прогона. Промежуточные checkpoint-отчёты не используются для измерений. Свидетель checks/missing-input-witness.json объясняет две неоднозначности исходных данных и не объясняет остальные технические пропуски. Чужие значения и ответы эталона не подставляются в построитель.

Правила Java сверены с [JLS, глава 15](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html), [String](https://docs.oracle.com/javase/8/docs/api/java/lang/String.html) и [Stream](https://docs.oracle.com/javase/8/docs/api/java/util/stream/Stream.html), включая обращения через Context7. При построении ответа эти сайты и внешние модели не используются.
