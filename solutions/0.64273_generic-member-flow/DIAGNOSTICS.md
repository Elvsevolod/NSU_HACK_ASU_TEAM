# Диагностика № 24

Поддержана подстановка исходных типов в поля и возвраты, композиция наследования, простые ограничения аргументов метода и явные аргументы типа. Wildcard capture, общее выведение наименьшего общего типа, все перегрузки и целевые контексты не реализованы. Тип не выбирается по форме Python-значения.

Для поддержанных native-скаляров класс упаковки отделён от полезной нагрузки. JSON-строка — String; ширина числа без объявления не угадывается. При возврате примитивного результата учитывается тип результата метода перед последующей упаковкой. Это ещё не полная модель памяти: локальные Object и обычные списки не везде сохраняют такие сведения.

Контрпример List<Long> → сырой alias → add(1) → типизированный get(0) ошибочно выполняет следующий вызов без диагностики. Он воспроизведён в experiments/20261018-generic-member-flow/next-native-list-probe.json и остаётся открытым. Сужающие приведения произвольных классов проекта тоже не полностью проверены. Нельзя утверждать, что все неподдержанные операции уже сопровождаются предупреждением.

Raw generic-поле и raw JSON сохраняют содержимое, но непроверенное уточнение аргумента не доказывает тип. Неизвестные входы общего прогона выросли с 45/130 до 47/138 (шаги/пары). Все сценарии частичны: 4514 возможных рёбер, 0 подтверждённых. Сокращение неизвестных в № 24 не достигнуто.

Новые семейства диагностики: unresolved_generic_cast, unresolved_native_cast, unresolved_generic_heap. Сохранено unresolved_collection_cast. Неопределённый implicit Map cast не объявляется гарантированным исключением: вставка JVM-проверки зависит от контекста потребителя после стирания типов. Генерируемые getters/setters используют проверки полей, но произвольные annotation processors не исполняются.

Сохраняются границы static storage, отдельных скрытых полей, reference-array stores, float, части compound conversions, циклических аргументов вызова и объединения обычных контейнеров. Ниже — исторические детали № 23; приведённые там счётчики относятся к предыдущему варианту.

## Исторические детали № 23

Изменение устраняет воспроизведённые потери записи и нарушения порядка вычисления. Оно не сокращает неизвестные входы данного открытого набора: остаются 45 шагов и 130 пар «шаг — поле». Удаления предупреждений ради метрики и подстановки отсутствующих значений не было.

`benchmark/lvalue-graphs.json` и `lvalue-parent22.json` сравнивают четыре фиксированных графа. `benchmark/development-review.json` перечисляет границы, контрпримеры и исправления собственных промежуточных ошибок. `code-sha256.json` связывает итоговый замер с исходниками. `analysis-report.json` хранит основания выбора и неопределённость. Счётчики относятся к анализу всех восьми сценариев, а не к оценке точности каждого отношения на скрытом эталоне.

Новые явные границы: `unsupported static or unresolved Java field write`, `hidden Java fields require separate declaring-class storage`, `reference array store runtime component type is not modeled`, `float rounding is not modeled`, `unsupported Java compound assignment conversion or operator`. Неизвестный индекс массива расширяет все потенциально изменённые компоненты, не выбирая произвольный индекс. Эти предупреждения не означают полную модель всех альтернатив исключений неподдержанного механизма.

Два класса одинакового короткого имени внутри разных владельцев различаются по бинарному имени. Для простой формы присваивания с родительскими скобками в левой части текущая грамматика tree-sitter может выдавать синтаксическую ошибку, хотя JLS допускает такую форму. Проверка не объявляет эту форму поддержанной: итоговый тест проверяет преобразование `null` на обычной записи поля. Первая проверка этой формы и первый замер до устранения неоднозначности вложенного класса сохранены в экспериментах.

Унаследованные ограничения сохраняются: неполная маршрутизация сложных условий конфигурации, фильтров, JSON-видимости и кодеков, библиотек и ветвлений при исчерпании бюджета; не все неизвестные значения имеют авторитетный источник во входных материалах. Входы сценариев начинают с независимого состояния. Один корректный S0, синтетические графы и проверки выбора обработчика не заменяют полного независимого эталона реального приложения.

Для следующего шага сохранена агрегированная таксономия `experiments/20261018-lvalue-evaluation/aggregate-operation-families.json`. Частые семейства — неопределённость JSON/JavaBeans, типы получателей и результаты методов доступа. Это основания для общих независимых проб, а не доказательство конкретной причины ошибки и не разрешение разбирать бизнес-действия отдельных сценариев ради подгонки.
