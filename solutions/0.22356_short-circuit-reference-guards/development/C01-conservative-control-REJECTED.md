# Не принятый дополнительный контроль

После первого TT прогона отдельно проверялся limit1 null-guard. Требование completion_splits==0 оказалось некорректным: source if имеет return и normal continuation, для которых существующий движок законно выделяет две completion alternatives. До дополнительного патча все пути уже завершались normally, без NPE. Следовательно, этот контроль не воспроизводит заявленный новый дефект. Дополнительное null_only/guarded_branch расширение полностью убрано, сохранены его captures. Рабочие code/test hashes точно совпадают с реально измеренными c01-full и tt-c01-command. Никто не подменял исходный TT прогон результатом другого кода.
