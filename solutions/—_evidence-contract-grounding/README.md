# Решение № 7 — evidence-contract-grounding

Родитель — № 6. Самостоятельный снимок кода, без импортов из других решений. Подготовлено 17 октября 2026 года. Анализатор работает на Python и не запускает Java, сервисы или SQL. Локальные и внешние модели при построении ответа не используются.

Связанный контракт обработчика и запроса интерфейса ранжируется BM25 по имени, маршруту, DTO и локальному действию JavaScript. Небольшой английский словарь различает чтение, создание и изменение; предметные имена извлекаются из входов. Поддержаны прямые запросы `$.ajax`/`$http`, ограниченные цепочки именованных обёрток, скобки, алиасы и `JSON.stringify`. Значения параметров получают происхождение из явного текста, контекста, UI, enum или истории. Отрицание отсутствующего поля из контекста может переопределить значение формы; новые неуказанные реквизиты остаются символическими.

Сохранены интерпретация Java AST, работа с предоставленным дампом, JPA и статические межсервисные связи родительского ядра. Потенциальная связь скелета сама по себе не становится доказательством выполнения. Неизвестные условия сохраняют альтернативы; при превышении бюджета используется отмеченное приближение. Явные конструкторы не исключаются по оценкам сайта.

## Запуск

Команды выполняются из папки решения. Поддерживается Python 3.11. Для другого проекта замените пути аргументов; контекст можно передать отдельным SQL-файлом. Граф должен иметь ту же схему.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py \
  --source ../../tt-challenge/targets/trainticket \
  --skeleton ../../tt-challenge/skeleton/trainticket.json.gz \
  --context ../../tt-challenge/context --scenarios ../../tt-challenge/scenarios \
  --output submission.json --report benchmark/analysis-report.json
```

`--path-limit` задаёт предел состояний (по умолчанию 4). `offline_run.py` блокирует сетевые соединения, запуск процессов и чтение эталонов/прежних ответов через Python audit hook. Это проверка Python-операций; системная изоляция нативных библиотек отдельно не заявляется. Веса и подготовка моделей не нужны. Индекс строится один раз на все сценарии.

Фактический итог pytest: **72 passed in 0.25s**. Независимые микропроекты склада и библиотеки проверяют параметры, отрицание, изменение БД между запросами и изоляцию сценариев. Двухсервисный пример магазина и платёжного журнала проверяет REST, `data` и следующий запрос к сохранённой записи. Эти небольшие примеры не подтверждают поддержку произвольных репозиториев. Отдельный процесс с другим ID сценария и `PYTHONHASHSEED=991` воспроизвёл все рёбра S0.

В отчёте `selection` хранит ранжирование и статус `lexical_hypothesis`, альтернативы — параметры, происхождение, состояния, условия и основания рёбер. `confirmed` означает обязательность относительно выбранного контракта и поддерживаемой семантики, а не подтверждение выбора HTTP-запроса или реальную трассу. `possible` отражает оставшиеся альтернативы и приближения. Проверка `verify_run.py` сопоставляет каждое ребро с основанием и проверяет разделение этих множеств.

## Ограничения и роль DeepSeek

Главное ограничение — лексический выбор запроса и неполные привязки параметров. Возможны путаница похожих API, выбор чтения одного объекта вместо списка, неверное разрешение роли или зависимости шагов. Нет полноценного SVO-парсера, семантической модели языка или общего типизированного реестра всех созданных сущностей. Отсутствующие сведения не следует считать доказанными значениями.

Java/Spring/ORM поддерживаются частично. Динамические маршруты, замыкания и затенение JS-функций, сложные HTTP-клиенты, рефлексия, произвольные ORM-запросы, транзакции и некоторые конструкции Java остаются приближениями. Интервалы № 8 ограничены простыми скалярами; поля объектов, исходно неизвестные алиасы, арифметические отношения и полный решатель Java-условий не поддерживаются. Условия с присваиваниями/инкрементами, смешанные числовые домены и потенциально неточные преобразования не уточняются. Правила округления сверены с [JLS 5.1.2](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.1.2). Предельные значения и все эффекты JVM отдельно не доказаны. Ktor и другие стеки не проверялись.

DeepSeek использовался при разработке через закреплённый бесплатный OpenCode: консультация по вариантам и узкая реализация разбора тел запросов с семью тестами. Codex прочитал весь его дифф, самостоятельно запустил проверки и добавил независимый тест разных URL. DeepSeek также нашёл два дефекта ограничений № 8; они воспроизведены и исправлены Codex. Дополнительный ответ ревью завершился по лимиту рассуждений без итогового текста и не считается одобрением; окончательная приёмка основана на проверках Codex. Предложения о неизвестных ветвях как «happy path», гарантии 100% JPA и удаление выполненных чистых методов не приняты. Журналы и приёмка находятся в `../../experiments/20261016-alternatives/`; они не нужны для запуска готового анализатора.

`solution.zip` содержит `submission.json` в корне, код, инструкции и сохранённые проверки. Архив на сайт не отправлялся. Материалы `tt-challenge/`, `sample/` и оценённые варианты № 1–5 проверены по 1321 SHA-256 и сохранены. № 6 и его отдельные продолжения ведутся другим чатом и не изменялись этим заданием.
