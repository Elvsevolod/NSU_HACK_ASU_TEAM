## Изменения и границы

Доказанное создание нативного com.fasterxml.jackson.databind.ObjectMapper() даёт отдельное состояние двух DeserializationFeature: FAIL_ON_UNKNOWN_PROPERTIES и FAIL_ON_NULL_FOR_PRIMITIVES. Поддержаны configure/enable/disable до первого чтения/записи, isEnabled и независимый copy. Общие ссылки, записи вызываемого метода и согласованные ветви сохраняют настройки. Неизвестная настройка, модуль, внешний вызов с mapper или конфигурация после использования оставляют диагностику и не сохраняют прежние настройки как доказанные.

Null примитива получает стандартное значение только при доказанной политике; boxed/reference null остаётся null. Пропущенное поле и explicit null различаются. Неизвестные свойства при доказанной политике дают отказ либо отбрасываются. convertValue оборачивает доказанный отказ в IllegalArgumentException, readValue сохраняет проверяемое семейство JSON-исключений. Точный подкласс не выдумывается; неподтверждённая совместимость catch сохраняет альтернативы. Одноимённые классы исходников и чужие imports не подменяют библиотечные исключения.

Значения полей и настройки берутся из исходников и наблюдённого состояния. Ключи JSON не создают внутренний тип mapper или enum. Учитываются побочные эффекты выражения перед статической enum-константой, включая null и отказ. Неподдержанные getters/setters/аннотации и неполная проекция payload не доказывают конкретный отказ. Настройки локального mapper не переносятся на HTTP-клиент. Полные JavaBeans, Jackson, JVM и жизненный цикл Spring не реализованы. [Подробные границы](DIAGNOSTICS.md), [ревью](benchmark/code-review.json), [первичные контракты](checks/library-contracts.json).

## Независимые проверки

[53 компонента, 48 семейств](benchmark/mechanism-comparison.json) используют одинаковые исходники и вручную заданные рёбра, сохранённые до предсказания обоих ядер. Точных графов **43 → 51 из 53**. Восемь исправленных семейств включают ветви JSON/null, копии и ссылки, null-получатель, выполнение выражения перед enum-константой, обработку отказа перед remote и data. В последнем случае data IoU **0 → 1**, remote в отдельном случае **0 → 1**. Два прежних ограничения — generic scalar binding и stream над Map view — остаются. Пустые отношения не считаются качеством 1; панель не является репрезентативной оценкой переносимости.

Добавлено 47 проверок; на замороженном № 18 из них 32 не проходят, на № 19 проходят все. Одна унаследованная проверка усилена: вместо предупреждения о неизвестной политике требуется доказанное исключение и остановка. Исходники № 18 не менялись.

Повторены [11 проб Petclinic](benchmark/petclinic.json) и ограниченная цепочка [GET → PUT → GET](benchmark/petclinic-body-graph.json) на тех же 78 исходниках и с тем же эталоном. Executes/calls/data совпадают, состояние сохраняется; remote пуст. Полного HTTP/security/validation/Jackson-эталона другого реального приложения по-прежнему нет. ## Воспроизводимость

Из каталога варианта, с Python 3.11:

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py --source /path/to/project --skeleton /path/to/skeleton.json.gz --context /path/to/context --scenarios /path/to/scenarios --output /tmp/submission.json --report /tmp/analysis-report.json
.venv/bin/python -B code/verify_run.py --submission /tmp/submission.json --report /tmp/analysis-report.json --output /tmp/verification.json
PYTHONPATH=code .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
~~~

Для входа репозитория: --source ../../tt-challenge/targets/trainticket, --skeleton ../../tt-challenge/skeleton/trainticket.json.gz, --context ../../tt-challenge/context, --scenarios ../../tt-challenge/scenarios. Эталон читает отдельная проверка после построения. Offline-аудит блокирует сеть, дочерние процессы и чтение эталона; проверены основания каждого ребра, другой ID S0 и hash seed. ZIP повторно проверяется из отдельного каталога на всех восьми сценариях и тестах.

В [ZIP](solution.zip) входят корневой submission.json, код с тестами, инструкция, независимые проверки и компактные результаты. Полные analysis-report/reproduction-report, промежуточные ответы и логи остаются в локальном benchmark и не включаются в отправляемый архив. Отчёт можно заново получить командой выше. Метаданные упаковки/повтора сохраняются рядом с ZIP после его создания; уже отправленный архив не пересобирается.

[Агрегаты неизвестности](benchmark/coverage-summary.json) не используются построителем. [Свидетель недостающих исходных данных](checks/missing-input-witness.json) объясняет две неоднозначности, а не остальные технические пропуски.

Последний запуск закреплённого бесплатного DeepSeek получил nonretryable403 до ответа или правок. Для № 19 новых API-повторов без изменения доступности не делали. Новые изменения выполнены и проверены Codex; другой моделью DeepSeek не заменяли. [Учёт](benchmark/deepseek-development.json). Унаследована ранее проверенная SQL-правка № 15.

Защищённые входы и прежние варианты сохранены; изменения метаданных № 18 относятся только к фиксации J и сверке скачанного архива. Код параллельного № 13 не исследовался и не менялся. [Проверка сохранности](benchmark/protected-files.json). Общая цель остаётся активной.
