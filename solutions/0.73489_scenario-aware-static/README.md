# Решение № 2 — scenario-aware-static

Родитель: решение № 1, baseline-nlp.

## Фича

Первая версия статического анализатора с отдельными местами вызова, выбором одного обработчика на шаг, разбором условий и учётом параметров сценария. Код на Python, без LLM и внешних API.

Из baseline сохранены поиск BM25 и извлечение контекста фронтенда. Новый код разбирает Java через Tree-sitter, связывает условия с конкретными вызовами, передаёт известные аргументы между методами, учитывает ранний возврат и ленивый вызов исключения. Добавлены правила выбора действий Train Ticket, проектные обработчики безопасности и чтение таблиц из SQL-дампа без запуска MySQL.

Каждый сценарий получает отдельную копию исходных данных. Достоверно достигнутые записи в репозиторий обновляют эту копию. Неизвестные условия сохраняют возможные ветки; неподтверждённые записи не превращаются в факт успешной операции. Это первая итерация, а не полная реализация семидневного плана.

## Запуск

Команды выполняются из папки этого решения. В репозитории пакет данных лежит на два уровня выше; после распаковки архива замените `../../tt-challenge` на путь к выданному пакету.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B code/run.py \
  --source ../../tt-challenge/targets/trainticket \
  --skeleton ../../tt-challenge/skeleton/trainticket.json.gz \
  --context ../../tt-challenge/context \
  --scenarios ../../tt-challenge/scenarios \
  --output submission.json \
  --report benchmark/analysis-report.json

python3 -B ../../tt-challenge/platform/evaluate_golden.py \
  ../../tt-challenge/gold/S0.json submission.json --json
```

Для одного сценария передайте его JSON в `--scenarios`. Можно также запускать `python -m analyzer` из каталога `code/` с теми же аргументами. Эталон не передаётся анализатору; он нужен только отдельному проверяющему скрипту.

## Проверки

Тесты проверяют истинные, ложные и неизвестные условия; ранний возврат; короткое вычисление логических выражений; отдельные места вызова; ленивый обработчик исключения; чтение SQL; изоляцию сценариев; разные наборы дополнительных услуг; выбор обработчиков; отсутствие наследования старого аккаунта новым пользователем.

Интеграционная проверка S0 запрещает сетевые соединения и чтение `gold`, меняет ID сценария и сравнивает полученные связи. Входной дамп остаётся неизменным. Результат запуска тестов находится в `benchmark/tests.txt`.

```bash
.venv/bin/python -m pip install pytest==9.1.1
TT_CHALLENGE_ROOT="../../tt-challenge" PYTHONPATH=code \
  .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
```

Проверка повторного запуска распакованного кода с другим именем каталога и другим `PYTHONHASHSEED` сохраняется в `benchmark/reproducibility.json`.

`benchmark/analysis-report.json` содержит выбранный обработчик и альтернативы каждого шага, параметры, проверенные условия, источники рёбер, известное состояние до и после шага и предупреждения. Разобраны 1537 объявлений методов, ошибок синтаксического разбора Java не обнаружено.

## Ограничения и следующая работа

- Разбор естественного языка использует словарь и правила Train Ticket. Перенос на другой проект потребует адаптера и совместимого скелета.
- Полная цепочка «покупка → оплата → выдача → отмена» пока не восстанавливается: в текущем отчёте новые заказы не становятся достоверно известными, потому что предшествующие условия остаются неизвестными. Поэтому S7 может содержать лишние ветки после отказа. Нужны более точные результаты поиска, привязка объектов и модели эффектов операций.
- Данные новой регистрации и административных действий извлекаются не полностью. Неизвестная новая учётная запись не заменяется существующим пассажиром.
- `switch` сохраняет альтернативы; обычные циклы приближаются одним проходом, коллекции ограничены 64 элементами. Неподдержанные конструкции и рекурсия требуют уточнения; применённые приближения отражены в отчёте.
- Дата и часть значений запросов соответствуют выданному контексту Train Ticket. Общего понимания произвольных дат и формулировок пока нет.
- Остаточные расхождения S0: лишние внутренние вызовы JWT и одна связь с таблицей ролей; недостающая связь с `getPassword`. Они не исправлялись прямым копированием рёбер эталона.
