## Запуск

Из папки варианта, с установленными `requirements.txt`:

```sh
python -B code/offline_run.py --source ../../tt-challenge/targets/trainticket --skeleton ../../tt-challenge/skeleton/trainticket.json.gz --context ../../tt-challenge/context --scenarios ../../tt-challenge/scenarios --output /tmp/solution29-replay.json --report /tmp/solution29-report.json
PYTHONPATH=code python -B -m pytest -q code/tests
```

`submission.json` не строится из эталона. Wrapper блокирует сеть, запуск процессов и чтение gold/reference/oracle. Оценивание выполняется отдельной программой после построения ответа. Приложения и JVM не запускаются. Общий path limit остаётся 4; резерв native completion не увеличен.

## Что подтверждено

1693 теста прошли. Все 103 шага сопоставлены с базой. Восемь оплат снова выбирают публичный `InsidePaymentController.pay`; оба поиска записей сохранены, восстановлены багаж без слова record и административный список заказов. Явные `state=1` и `enableStateQuery=true` сохранены в фактическом DTO всех альтернатив S0/5. Корректный HTTP-запрос оплаты существующего неоплаченного заказа проходит чтение баланса, обновление заказа и сохранение платежа; отсутствующий заказ отклоняется до записи.

Независимый синтетический документооборот проверен отдельно с HTTP и NL: список → выбор ID и revision → изменение → remote 503 → fallback → чтение нового состояния; все четыре отношения сравниваются на каждом шаге. Это регрессия общего механизма, не независимое реальное приложение.

На исходниках реального PiggyMetrics пройдены восемь шагов и три дополнительных контроля, строгие wire/args/result/state/callback проверки и отдельная проекция всех четырёх отношений. При лимитах 1/4/8 основная цепочка детерминирована; стресс ветвления подтверждается другими тестами. Все 16 мутаций трасс отклонены. Oracle v3 независимо прочитан субагентом Codex по разрешению пользователя; v2 сохранён без изменения. PiggyMetrics-профиль получает явно предоставленные OAuth-контексты и не считается тестом login. Отдельные source-login проверки сами получают JWT и проверяют следующий запрос, неверный пароль, disabled, другого actor, подделку и expiry.

## Существенные ограничения

Полный NL-путь Train Ticket не восстановлен: поиск поездов всё ещё теряет точность на обходах неупорядоченных Map/списков; последующие ID могут оставаться неизвестными. У admin UI и passenger UI разные ключи storage; успешный admin login не создаёт вымышленную passenger-сессию. Два действия просмотра магазинов имеют неоднозначные обработчики и неполные параметры. В полном прогоне остаются 533 остановки по completion budget, 195 моделируемых uncaught application exception, две ошибки HTTP binding и четыре явные unsupported boundaries. Это альтернативы, а не число сценариев и не ошибки Python.

S0 не улучшился относительно № 28. Legacy NL-профили Petclinic и PiggyMetrics не проходят полную приёмку: Petclinic IoU E/C/D = 0,7333/0,6364/1; PiggyMetrics E/C/D = 0,875/1/1; remote там отсутствует. Эти результаты сохранены, не заменены успешным новым профилем. Новый полноценный профиль реального приложения согласования документов не подготовлен; предложенная в аналитике предметная область покрыта синтетическим контролем. Универсальность не заявляется.

Подробности, все этапы и границы контрактов: `IMPLEMENTATION_REVIEW.md`, `development/requirements.json`, `benchmark/stage-comparison.json`. Полные трассы лежат в `benchmark/stages/*/analysis-report.json.gz`; этап M с ошибкой кодирования сохранён как неуспешный, исправление — M2.
