# Матрица поддержки понижения (N03/N04)

Документ фиксирует **границы** модели выполнения: что понижается в
упорядоченный IR, что понижается частично, а что осознанно не моделируется.
Числа получены измерением, а не оценкой:

```text
cargo run --release --example lowering_census --manifest-path semarch/Cargo.toml \
  -p semarch-tt -- tt-challenge/targets
```

Измеренный корпус (2026-10-18): **635** Java-файлов `tt-challenge/targets`
(включая модули вне скелета), **2 815** тел функций, **7 274** базовых блока,
**24 087** операторов, **1 485** охран, **3 298** выходных блока,
**0** структурно некорректных тел (`lowering::validate`).

Правило чтения таблицы: «понижается» означает, что конструкция становится
блоками и терминаторами; «частично» — что часть эффектов сохранена, а
несмоделированное записано как `AnalysisGap`; «не моделируется» — что записан
`AnalysisGap` с причиной, и это **не** молчаливый пропуск.

## Java

| конструкция | статус | как представлена / причина пробела |
|---|---|---|
| блок, `constructor_body` | понижается | `lower_sequence` |
| `if` / `else if` / `else` | понижается | `Branch` + общий join-block |
| `while`, `do…while`, `for`, `for (T x : xs)` | понижается | заголовок с обратным ребром; `do` входит в тело до проверки |
| `return`, `throw` | понижается | `Return` / `Throw`, выход из тела |
| `local_variable_declaration`, `x = …`, `x += …`, `x++` | понижается | `Assign` (инкремент как `x + 1`) |
| `try` / `catch` / `finally` | частично | `finally` встраивается во **все** завершения (возврат, нормальный путь, каждый `catch`); завершение-aware: значение `return` снимается в временную **до** тела `finally` (B38-06), а `return`/`throw` внутри `finally` **отменяет** переносимое завершение; выбор `catch`-ветви — `ExceptionDispatch` |
| `try (resource)` | частично | тело понижается; закрытие ресурса не моделируется |
| `synchronized` | частично | тело понижается; взаимное исключение не моделируется |
| `switch` (statement) | частично | контейнерный `Terminator::Gap`; тела `case` остаются как may-execute |
| `break` / `continue` / метки | частично | `Gap` «abrupt control flow without label tracking» |
| `assert` | не моделируется | `UnsupportedStatement` |
| тернарный оператор | понижается | два блока, общий временный `$t<n>`, затем join; `Goto join` ставится на **выход** плеча, а не на блок входа, поэтому вложенный тернарный оператор не теряется (B38-06) |
| `&&` / `\|\|` | понижается | ветвление по левому операнду, правый — в своём блоке |
| `instanceof`, лямбда в позиции значения, ссылка на метод, `x = y = z` | не моделируется | `UnsupportedExpression` (сохраняется как значение `Unknown`) |
| `new Foo(…)` | частично | аргументы понижаются по порядку; сам вызов конструктора — `NotInFactContract` (не место вызова в плоских фактах) |
| `this(…)` / `super(…)` | частично | аргументы понижаются; делегирование — `NotInFactContract` |
| `Foo.class` | понижается | статическая ссылка (`Symbolic`), эффектов нет |
| `a[i]`, `a[i] = v` | частично | чтение даёт `Unknown`; запись — провал в состояние («array element state is not modeled») |
| `a.b`, `this`, `super` | понижается | `ValueExpr::Field` / `Symbolic` |
| преобразования (`(T) x`, `(int) y`) | понижается | прозрачно для значения |
| лямбды и анонимные классы | не моделируется | тела **не** входят в тело объемлющего метода; их методы не понижаются |
| поля и статические инициализаторы | не моделируется | не являются `FunctionBody`; плоский обход их вызовы тоже не регистрирует (см. ниже) |

## Python

| конструкция | статус | как представлена / причина пробела |
|---|---|---|
| suite (`block`) | понижается | `lower_sequence` |
| `if` / `elif` / `else` | понижается | `Branch` + join; `elif` — вложенное условие |
| `while`, `for` | понижается | заголовок с обратным ребром |
| `while … else`, `for … else` | понижается | `else` — отдельный путь, достижимый по нормальному выходу |
| `return`, `raise` | понижается | `Return` / `Throw`; неявный `return None` добавляется |
| `x = …`, `x += …` | понижается | `Assign` (в Python это `expression_statement` → `assignment`, не выражение) |
| `a < b < c` | понижается | цепочка сравнений как `(a<b) and (b<c)`; `is`/`is not` — равенство/неравенство |
| `and` / `or` | понижается | возвращают **операнд**, а не `bool` |
| `not`, `-x`, `~x` | понижается | `not` всегда `bool` |
| тернарный `a if c else b` | понижается | два блока + join; части берутся **позиционно** (`consequence if condition else alternative`) — грамматика Python не объявляет полей у `conditional_expression`; `Goto join` ставится на выход плеча (B38-06) |
| `try` / `except` / `finally` | частично | `finally` встраивается во все завершения, включая `except`-ветви, завершение-aware (значение `return` снимается до `finally`, `return`/`raise` в `finally` отменяет переносимое завершение); выбор `except` — `ExceptionDispatch` |
| `with` | частично | тело понижается; протокол контекстного менеджера не моделируется |
| `match` | частично | тело остаётся may-execute; выбор ветви не моделируется |
| `assert`, `del` | не моделируется | `UnsupportedStatement` |
| списочные включения, генераторы | не моделируется | `UnsupportedExpression` |
| `await`, `yield` | не моделируется | тела с ними не понижаются как синхронный поток |
| лямбды | не моделируется | тело лямбды не входит в тело функции |
| `global` / `nonlocal` / `pass` / комментарии / импорты | игнорируются намеренно | у них нет эффектов в модели |

## Семантика значений (общая для обоих языков)

| свойство | правило |
|---|---|
| целые | точные `i64`; переполнение → причина, не значение |
| деление | целочисленное в Java/Go/C#, вещественное в Python/JS |
| остаток | при разных знаках операндов не вычисляется (языки расходятся) |
| деление на ноль | причина (`integer_…` / `floating_…`), не значение |
| равенство | между тегами определено (`1 == 1.0` истинно, `None == 0` ложно) |
| `Unknown` | не решает ничего: `Unknown == 0` — это `Unknown`, не `false` |
| `Unreachable` | bottom: поглощает операции, не является значением |
| истинность | Java/Go/C# — только `bool`; Python/JS/TS — falsy-значения |
| `&&`/`\|\|` | Java/Go/C# — булевы (Клини); Python/JS/TS — возвращают операнд |

## Измеренные пробелы на корпусе

Всего **3 153** записи; распределение по причинам:

| причина | число | что это |
|---|---|---|
| `NotInFactContract` | 2 692 | 2 652 — `new` (не место вызова в плоских фактах), 40 — делегирование `this(…)`/`super(…)` |
| `ExceptionDispatch` | 69 | выбор `catch`-ветви по брошенному значению |
| `UnresolvedCall` | 168 | плоские факты не содержат места вызова для `getMsg`, `getPrice`, `get`, `toString`, `getTripId`, `spanNamer`, `traceKeys`, `currentTimeMillis`, `tracer`, `create`, `getData` — это дыры **контракта**, найденные понижением |
| `UnsupportedExpression` | 168 | 29 `instanceof`, 29 лямбда в позиции значения, 9 ссылок на метод, 7 `dimensions_expr`, 5 цепочек присваивания и длинный хвост |
| `UnsupportedStatement` | 56 | 48 записей в массив, 8 `synchronized`, `assert` |

### Что этот список доказывает

1. Пробелы **не** растворены в молчании: каждая неподдержанная конструкция имеет
   причину, диапазон и (для блочных) привязку к блоку.
2. `UnresolvedCall` на `getMsg`/`getPrice` — это не дефект понижения, а
   наблюдаемая неполнота плоского контракта (например, вызов внутри тернарного
   оператора в `return`, который плоский обход не посещает). Такие места
   полезны как backlog: исправление изменит конкурсный ответ, поэтому вынесено
   из N03/N04.
3. Две трети числа пробелов — `new`, и это ровно один и тот же пробел контракта.
   Именно поэтому введён отдельный `GapReason::NotInFactContract`: иначе
   измерение не позволяло бы отличить «мы не умеем» от «контракт не несёт».

## Чего в матрице нет намеренно

* Никаких правил, зависящих от имён Train Ticket (`ts-auth-service`,
  `OrderController`, `verifyCode`): понижение читает только синтаксис языка.
* Никаких «эвристик на сценарий»: `docs/adr/0003` и generality-gate запрещают.
* Полноты Java/Python не заявляется: таблицы выше — это и есть граница.

# Матрица поддержки привязки запроса и движка состояний (N05/N06)

Документ фиксирует **границы** того, откуда движок берёт значения и как далеко
они распространяются. Правило чтения: «берётся» — значение известно и
типизировано; «частично» — известна часть, остальное записано провенансом или
пробелом; «не берётся» — значение остаётся `Unknown`, и это записано как
провенанс, а не молчание.

## Откуда берётся значение поля

| источник | статус | как представлено |
|---|---|---|
| payload-клауза шага (названное значение) | берётся | `BoundValue::Literal` + `origin: payload` |
| «пусто»/«blank» перед упоминанием поля | берётся | `BoundValue::Empty` (для ссылочного типа — `""`) |
| «without»/«no»/«missing»/… перед полем | берётся | `BoundValue::Absent`; `Null` даётся только с доказательством — поле без инициализатора **и** тело десериализуется (`@RequestBody`/`@ModelAttribute`); примитив — `Unknown` (B38-04) |
| заявление пакета о стартовом состоянии (`context/README.md`) | берётся | `BoundValue::Absent` + `origin: context` и провенанс клаузы, если шаг ей не противоречит; молчание шага само по себе отсутствием не является (B38-04) |
| статическая `<option>` выбранного элемента | берётся | `BoundValue::Literal` + `origin: ui_option` |
| список опций, подтягиваемый в рантайме (`{{item.value}}`) | частично | шаблон отбрасывается; поле остаётся `Unknown` (`value_not_in_source`) |
| молчание шага о поле | не берётся | `BoundValue::Unknown` + `origin: unmentioned` |
| слово payload, не назвавшее объявленного поля | не берётся | запись в `unmatched` |
| значение без объявленного типа | не берётся | `Literal` в отчёте, но в `Env` не попадает (`value_without_declared_type`) |

Объявление полей и типов читается из данных проекта (скелет: `field`-узлы,
`type`/`type_raw`). «Рамочные» типы (`java.`, `javax.`, `jakarta.`,
`org.springframework.`) не считаются телом запроса.

## Как значение распространяется

| канал | статус | правило |
|---|---|---|
| `x.getField()` (JavaBeans) | берётся | только по квалифицированному ключу `<receiver>.<field>`; профиль языка решает, есть ли аксессоры |
| локальная переменная `T v = expr;` | берётся | значение присваивания в `Env` этой ветви |
| фактический аргумент-символ | берётся | связанные свойства вызывающего переезжают под имя параметра вызываемого; скалярная переменная вызывающего привязывается **по значению** (B38-05) |
| фактический литерал | берётся | параметр получает литеральное значение |
| копия значения (примитив из поля, результат помощника) | не берётся | параметр вызываемого остаётся несвязанным |
| поле объекта между методами (куча) | не берётся | N08; значение остаётся `Unknown` |
| константа перечисления из исходников | не берётся | значение не читается; статическая опция может связать, иначе `Unknown` |
| индексация массива `a[i]` | не берётся | чтение даёт `Unknown` (см. матрицу понижения) |

## Что делает движок с решением

| ситуация | поведение |
|---|---|
| тело понижено без пробелов, охрана решена | место вызова живо или подавлено; решение в `decisions` (`proves_true`/`proves_false`) |
| охрана не решена | место вызова живо; ребро `status = possible` |
| решение принято на свидетельском пути с меткой `gap:` | **не** считается доказательством: значение прочитано после несмоделированной конструкции, место вызова живо (B38-05) |
| блок доказан недостижимым решением без `gap:` на пути | место вызова не разворачивается, и запись в `suppressions` — с сертификатом: охрана, строка, вердикт, свидетельский путь, блоки (B38-05, ADR 0008) |
| место вызова понижено, но доказательства нет | остаётся живым с причиной `no_exclusion_certificate` |
| места вызова нет в пониженном теле | остаётся живым, счётчик `skeleton_site_absent_from_lowered_body` |
| нет пониженного тела (прокси, библиотека) | все места вызова метода живы, как в legacy, счётчик `methods_without_body` |
| конструкция внутри мёртвого плеча | её содержимое **не оживает**: gap-содержимое достижимо только из блока-владельца (B38-05) |
| исчерпан бюджет посещений | запись `method_budget_exhausted`, обход останавливается |
| G6 (слова сценария) | в этом пути **не** применяется: ветку решает значение; расхождение печатается в дифф |
| объединение по шагам | только после последнего шага; `StepOutcome` каждого шага независим |

## Чего в этой матрице нет намеренно

* Ни одной таблицы «сценарий → значение»: значение выводится из слов шага,
  объявлений проекта и статических опций. Адаптер формата — да, таблица — нет.
* Ни одного имени Train Ticket: проверка `generality.rs` строит игрушечный
  проект дважды, во втором переименовано всё, включая прозу шага.
* Ни одного «додуманного» результата: нерешённое остаётся `Unknown`/`possible`
  и попадает в `gaps`, `suppressed` или дифф.
