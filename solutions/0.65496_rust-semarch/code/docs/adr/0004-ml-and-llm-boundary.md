# ADR 0004 — Граница между ML, LLM и движком решения

* Статус: Accepted
* Дата: день 2

## Контекст

Условия конкурса разрешают ML и поиск по тексту, но запрещают запуск проекта и
рантайм-трассы. Организаторы перезапускают сданный код **офлайн**, без внешних
API: значит, ответ обязан воспроизводиться детерминированно на их машине.

Одновременно инструмент задуман как «пара к LLM»: модель полезна для ориентации
(сопоставление формулировки шага с обработчиком, подсказки по стекам), но
доверять ей генерацию правил нельзя — правил, выведенных из имени сценария,
проверить нечем, а абляцию к ним не построить.

## Решение

### Роли ML ограничены четырьмя слотами

| слот | что делает | статус |
|---|---|---|
| **M1. BM25** | ранжирование входных обработчиков по маршрутам и текстам UI | **в контуре**, обязателен |
| **M2. локальная переранжировка** (ONNX bi-encoder) | переоценка топ-N кандидатов M1 | выключена по критерию |
| **M3. TF-IDF-подбор привязки** (протокол × биндинг) | выбор клиента/библиотеки по тексту объявления зависимости | спроектирован, не включён |
| **M4. семантическая привязка шаг↔сервис** | мягкое сопоставление шага с модулем/сущностью | спроектирован, не включён |

Ни один слот не порождает правил: всё, что влияет на ответ, выражено механизмом
из ADR 0003 и проверяется абляцией.

### Критерий включения M2

Слот включается, только если **измеренная** точность M1 падает ниже порога:
доля шагов, у которых правильный обработчик попал в выбранный набор кандидатов,
меньше 0,95. Измерение ведётся по единственному размеченному сценарию (S0):
на нём M1 даёт 6/6 шагов с верным обработчиком в наборе и 5/5 нужных входов на
первом месте. Критерий не выполняется — M2 остаётся выключенной, и в ответе нет
ни одной величины, зависящей от модели.

### Файл модели

Файл модели **можно** хранить прямо в репозитории: каталог `models/`, обычный
git. Контракт при этом такой:

1. ответ обязан воспроизводиться **без** файла модели — путь по умолчанию
   детерминированный и не требует ни модели, ни сети;
2. модель подключается явным флагом (`--reranker onnx` в будущем слоте) и
   только при наличии файла; отсутствие файла не ошибка, а откат к M1;
3. одно и то же дерево исходников даёт **побайтово одинаковый** `submission.json`
   независимо от окружения: никаких переменных среды, времени, часового пояса и
   порядка обхода `HashMap` в ответе нет (все множества ответа — отсортированные,
   обход — с фиксированным бюджетом).

### Граница с LLM

* LLM **не** участвует в контуре принятия решения и не вызывается из инструмента:
  организаторский прогон офлайновый, внешних API нет.
* LLM и человек — **потребители** аудит-следа: `semarch tt-report` выдаёт на
  каждое ребро место вызова (`файл:строка`, получатель), тип связи скелета и
  основание, а на каждое неисполненное место вызова — признак, который его
  оживит. Это позволяет проверять путь руками или отдавать его модели на ревью,
  не доверяя движку.
* Гипотеза LLM (например, «эта ветка в этом сценарии не исполняется») попадает
  в ответ только после того, как выражена как механизм общего вида и подтверждена
  абляцией на открытом сценарии. Никаких «поправок для S3» в коде нет и не будет.

## Последствия

* Инструмент остаётся лёгким: зависимостей уровня «сервер инференса» нет, модель
  не нужна для воспроизведения ответа.
* Любое будущее включение ML обязано принести измерение (точность M1 до и после)
  и абляцию, иначе слот остаётся выключенным.
* Отчёт `report.json` — обязательная часть поставки: без него ответ нельзя
  проверить иначе как повторным прогоном.
