# ADR 0008 — Владелец пробела, честность пути и сертификат отсечения (B38)

* Статус: Accepted
* Дата: 2026-10-19
* Связан: ADR 0006 (упорядоченный IR и анализ значений), ADR 0007 (привязка
  запроса и движок состояний), ADR 0005 (привязка входа к шагу)

## Контекст

ADR 0007 дал движку значения: связанный запрос, решения охран, распространение
объектов между методами. Первая версия отсечения (N06) решала одну задачу —
«не потерять ребро, которое legacy находит» — и решила её грубо: если в теле
метода есть **хоть один** `AnalysisGap`, значение-отсечение для всего метода
выключалось (`pruning_disabled_by_lowering_gaps`), а сами gap-блоки
размечались достижимыми с пустым окружением «на всякий случай». Замер на
восьми сценариях показал, чем это обернулось:

* движок добавлял к ответу legacy ровно пять рёбер на сценарий, и все пять были
  ложными: gap-содержимое, размоченное как достижимое ниоткуда, оживляло вызовы
  внутри плеча, которое охрана только что доказала мёртвым (`new HttpEntity` в
  `TokenServiceImpl#getToken` возвращал к жизни `restTemplate.exchange`, то есть
  вызов сервиса кодов подтверждения, который сценарий как раз исключает);
* на S0 это дало 0.618 при 0.926 у legacy — среднее четырёх IoU с этими пятью
  ложными срабатываниями и одним ложным `remote`;
* отсечение «по причине» без свидетеля делало невозможным ответ на вопрос
  «почему это ребро убрано»: `exclusion_reason` утверждал «CFG доказал
  недостижимость», не называя ни охран, ни вердикта.

Ограничения остаются прежними (ADR 0006/0007): ответ конкурса не меняется,
никаких правил по именам Train Ticket, `unknown != false`.

## Решение

### 1. У пробела есть владелец (`semarch-core/src/ir.rs`, `lowering.rs`)

`AnalysisGap { reason, detail, span, block, owner }`. `block` — блок
содержимого пробела, `owner` — блок, чьё **нормальное продолжение** идёт рядом с
несмоделированной конструкцией (его проставляет фронтенд в
`BodyBuilder::gap_block(..., owner)`; все пять мест вызова передают текущий
блок). Анализ больше не размечает gap-блоки достижимыми: содержимое — это
**may**-переход из владельца, с окружением владельца и меткой свидетельского
пути `gap:<reason>`. Следствия:

* содержимое конструкции в мёртвом плече остаётся мёртвым;
* содержимое на живом пути анализируется со значениями этого пути;
* `BodyAnalysis.tainted_blocks` перечисляет блоки, достигнутые только по такому
  пути.

### 2. Честность свидетельского пути (`semarch-core/src/analysis.rs`)

Решение принимается на пути **без** метки `gap:`. Если конструкция могла
изменить отслеживаемые значения (`UnsupportedStatement`,
`UnsupportedExpression`, `Widened`), она «пачкает» и нормальное продолжение:
вердикт после неё доказательством не считается. Чистые пробелы значения
(`NotInFactContract`, создание объекта) продолжение не пачкают — они не меняют
ни одной связанной переменной.

### 3. Сертификат на каждое отсечение (`semarch-tt/src/engine.rs`)

Глобальное вето и `exclusion_reason` удалены. Вместо них:

* `dead_blocks(body, analysis)` — для каждого решения без `gap:` на пути
  обходит плечо, которое вердикт отсекает (`dead_arm`, с остановкой на любом
  блоке, достижимом другим путём: общий выход не мёртв), и возвращает блоки
  вместе с решением: `DeadBlock { guard, line, verdict, path, block, blocks }`;
* `block_of_call_site(body)` — в каком блоке лежит каждое понижённое место
  вызова;
* место вызова отбрасывается, **только** если его блок в этом множестве, и
  отбрасывание записывается как `Suppression { call_site, callee, certificate }`;
* всё остальное остаётся живым с причиной `no_exclusion_certificate`, а место
  вызова, которого нет в пониженном теле, — с
  `skeleton_site_absent_from_lowered_body`; метод без тела считается
  `methods_without_body`.

### 4. Наблюдение вызова в точке исполнения (`semarch-core/src/analysis.rs`, `semarch-tt/src/engine.rs`)

`CallObservation { env, receiver, args }` записывается на каждое
`(блок, место вызова)` — receiver и аргументы вычисляются в **локальном**
окружении блока, а не в состоянии входа в метод, и объединяются при повторных
посещениях. Движок входит в вызываемый метод с этим окружением:
`bind_arguments` берёт наблюдаемые аргументы, скалярная переменная
вызывающего привязывается по значению, а не только по передаче свойств.
Множество посещённых состояний ключуется парой `(метод, отпечаток окружения)`:
один и тот же метод с двумя разными значениями аргумента — это два анализа, а
не один.

### 5. Завершение-aware понижение (`semarch-frontend-java`, `semarch-frontend-python`)

`inline_finally` возвращает `Option<BlockId>`: `None` — тело `finally`
разошлось (`return`/`throw`), и переносимое завершение **отменяется**;
`lower_return`/`lower_throw` снимают значение в временную **до** тела `finally`
и не выпускают собственный терминатор, если тело разошлось. Плечо тернарного
оператора завершается `Goto join` на своём **выходе**, а не на блоке входа (в
Python части берутся позиционно — грамматика не объявляет полей у
`conditional_expression`).

## Что это дало (измерено)

* S0: семантический ответ 0.618 → **0.9260149572649572**, побайтово равен
  legacy на всех восьми сценариях (`only_legacy = 0`, `only_semantic = 0`);
  «выигранные» пять рёбер оказались ложными, и их удаление — не потеря, а
  исправление.
* На реальном `TokenServiceImpl#getToken` шаг логина теперь даёт полную цепочку:
  вход `UserController#getToken` → `verificationCode = absent (context)` →
  решение `g0` строка 65 `proves_false` → три отсечённых места вызова
  (`exchange@67:55`, `getBody@72:29`, `info@76:24`) с одним сертификатом
  (блоки `[2,4,5,6]`). Это пиннится тестом
  `crates/semarch-tt/tests/b38_login_gate.rs`.
* Отсечение ничего не отбрасывает без сертификата; причина
  `lowering_gaps_disable_pruning` исчезла из счётчиков.

## Цена и границы

* Сертификат — про **блок**, а не про значение: место вызова считается мёртвым,
  если мёртв его блок. Место вызова, чей блок достижим, но чьё значение
  несовместимо с ветвью, остаётся живым (консервативно).
* На S0 остаются ложноположительные рёбра, для которых нет решения: два
  `executes`, два `calls`, один `data`. Движок их сохраняет и считает — это
  правильное поведение доказывающего инструмента; оценка от этого не растёт.
* Совпадение с legacy на восьми сценариях — измеренный факт, а не инвариант:
  движок имеет право разойтись, и тогда расхождение обязано быть объяснено
  (сертификатом, причиной сохранения или пробелом).
* Кучи, копий значений через аргументы-примитивы из поля и N08 остаются
  границами (см. матрицу поддержки): их `Unknown` — честный, а не молчаливый.
