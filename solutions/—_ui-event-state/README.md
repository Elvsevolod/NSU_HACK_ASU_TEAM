## Что исправлено

- Сохраняются HTTP-методы GET/POST/exchange, URI variables, тело, заголовки и статус. Ошибочный HTTP-ответ прекращает стандартный клиентский вызов; неизвестная пользовательская политика ошибок диагностируется.
- Пустой Optional, null и гарантированные ошибки индекса останавливают текущий путь. FilterChain вызывает контроллер внутри цепочки; учитывается shouldNotFilter. Исправлены switch, typed catch и finally.
- UUID остаётся типизированным символом с корректной формой; строковое преобразование и HTTP-путь сохраняют идентичность. Генератор Hibernate распознаётся по исходному объявлению, не по названию поля.
- Учитываются единицы массы, поддержанные шаблоны форматирования, порядок колонок INSERT, SQL-экранирование, заголовок и описание сценария, унаследованные поля и методы. Переполнение int/long следует исходной ширине; неподдержанная числовая семантика явно ограничена.
- List.contains использует исходный equals вместо допущения о поле id. Записанные вложенные объекты и перечисления сохраняются при повторном чтении. Нельзя перенести GeneratedValue на соседнюю сущность одного файла.
- HTML5-разбор событий строк, параметры событий, полные копии массивов ответа и проекции формы улучшают связывание UI. Предполагаемая подготовка формы помечается как непроверенное выполнение события.

Факты проекта, связывание сценария и выполнение находятся в отдельных модулях project/frontend, contracts и engine/paths/state. Бизнес-имена, маршруты и идентификаторы рёбер извлекаются из входов. Подстановка имён Train Ticket и поведение по ID сценариев в построитель не добавлены.

## Воспроизведение

Из каталога варианта, Python 3.11:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py --source ../../tt-challenge/targets/trainticket --skeleton ../../tt-challenge/skeleton/trainticket.json.gz --context ../../tt-challenge/context/db-after-warmup.sql.gz --scenarios ../../tt-challenge/scenarios --output /tmp/solution11-reproduced.json --report /tmp/solution11-report.json
PYTHONPATH=code .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
```

Другой проект подключается заменой source, skeleton, context и scenarios. Контекст текста берётся из skeleton.context, базы — из MySQL-дампа. Готовый граф-скелет обязателен. JVM и сервисы не запускаются. Установка пакетов требует их доступности; сам анализ работает без сетевых API и моделей. [Offline-аудит](benchmark/analysis-report-offline-audit.json): сетевых, процессных и эталонных обращений не было. Отдельный запуск копии вне репозитория с входным каталогом sample тоже прошёл: [отчёт](benchmark/standalone-sample-input.json).

## Проверки и ограничения

[489 регрессионных тестов](benchmark/tests.stdout.txt), [проверка формата и оснований](benchmark/verification.json), [воспроизводимость](benchmark/reproducibility.json) и [независимые микропроекты](benchmark/generalization.json) проходят. На настоящих исходниках Petclinic REST v2.1.5 проверены 11 выборов обработчика/параметров и полные графы ограниченной цепочки GET → PUT → GET: executes/calls/data IoU=1, изменение состояния сохранено. Это сравнение тел контроллера и сервиса при заранее разрешённом доступе и успешной валидации. **Полный HTTP-граф с security, validation и Jackson не проверен; remote в этой цепочке пуст.** [Границы и результаты](benchmark/petclinic-body-graph.json), [независимо перечисленный эталон](benchmark/petclinic-body-reference.json), [предсказание](benchmark/petclinic-body-prediction.json).

Универсальность на произвольных приложениях не доказана. Ограничены JVM, транзакции, JPA, Jackson, Spring security/conditional beans и браузер. fetch/axios и Vue SFC не поддержаны и видны в диагностике; Ktor не реализован. API выбирается как проверяемая лексическая гипотеза. Часть входных значений отсутствует в предоставленных материалах, часть теряется из-за ещё неполной семантики. Они перечислены в [DIAGNOSTICS.md](DIAGNOSTICS.md) и [аудите всех альтернатив](benchmark/input-coverage.json). Счётчик не означает, что известны конкретные байты генерируемых UUID или свободных символических входов.
