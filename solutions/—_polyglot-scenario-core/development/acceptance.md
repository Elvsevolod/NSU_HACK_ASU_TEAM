# Проверяемая цель

1. Оба фронтенда создают одни и те же типы IR; ядро не импортирует AST языков и бизнес-имена.
2. Общие ветви, return/throw/catch/finally, HTTP, состояние, доказательства и ограничения путей проверены контрпримерами. Различия арифметики Java/Python сохраняются.
3. Одна команда принимает source/skeleton/context/scenarios. Внешние модели и запуск приложения не нужны. IDs только из входного скелета. Неизвестные эффекты не превращаются в подтверждённые связи.
4. Проверены независимые исходники Java и Python, состояние между запросами и смешанный HTTP-сценарий. Ручные эталоны отделены от анализатора. Маленькие примеры не объявляются доказательством универсальности.
5. Холодная подготовка, повторное выполнение и память измерены отдельно. Сохранены submission, строгая проверка формата, SHA-256 и воспроизводимый ZIP. Предыдущие файлы сверены с манифестом.

Объём первой версии: bounded source interpreter с явными диагностическими границами. Полная семантика JVM, Python, framework security/validation/transactions и произвольный язык не обещаются.
