# Проверенные замечания после подключения OSS

Самостоятельный adversarial проход Codex обнаружил потерю расширения Java int → long: `int n; n < 2147483648L` ошибочно отсекался Z3, потому что boolean-формула не сохраняла разрядность операндов. До исправления правильная ветвь была признана UNSAT и в ответ попадал невозможный вызов. Сохранён исходный снимок `experiments/20261017-polyglot-scenario-core/before-review-fixes.zip` и воспроизведение `independent-review-failures.json`.

Формула теперь сохраняет operand_sort. Frontend передаёт типы полей и однозначные return types проектных методов, cast и ограниченных библиотечных контрактов. Неизвестный числовой тип не даёт оснований для сужения и отсечения. Проверены long literal, return long, long field и Long.parseLong в одном выражении с int. Правило соответствует [JLS 5.6](https://docs.oracle.com/javase/specs/jls/se25/html/jls-5.html#jls-5.6); контракт parseLong — [Java API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Long.html#parseLong(java.lang.String)). Полный type checker JVM этим не заменяется.

Второй дефект: сдвиг ошибочно расширял левый int из-за правого long и не маскировал конкретное расстояние. Java использует тип левого операнда и младшие 5/6 бит расстояния. Исправлены конкретные и символические <<, >>, >>>, включая отрицательное расстояние; Z3 LShR используется для unsigned shift. Основание — [JLS 15.19](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.19).

Другие исправления этого этапа проверены в test_oss_components.py: Python lexical shadowing и aliases; SQL quoted names/comments/versioned commands; NULL и empty COUNT; static Java fields не являются instance/ORM fields; Session binding; add без flush; flush → read → rollback; происхождение отложенной записи; Result.mappings/scalars/cardinality; семантика чисел после Java → Python HTTP. Прежние проверки не ослаблялись; синтетические Session-примеры получили явный engine, чтобы не доказывать выполнение через реально unbound Session.

Консультация DeepSeek по исходной архитектуре завершена. Проверка отдельных эталонов завершилась HTTP 403. Дополнительный OSS-проход выполнил только чтения; после 55 с был продолжен в той же сессии, за следующие 170 с не дал ни событий, ни содержательного вывода. Его выводы не принимались, завершённым ревью он не считается. Права edit/bash/task/external_directory были deny; замечания выше найдены и воспроизведены Codex.

Результат этого этапа остаётся архитектурным прототипом. На полном наборе качество ограничивают прежде всего NL/UI/context grounding и lifecycle фреймворка. Следующие улучшения следует проверять на независимых корпусах и сравнивать при одинаковом покрытии; количество подключённых библиотек, тестов или скорость на малом покрытии сами по себе не доказывают качество.

Поздние контрпримеры проверили область эффекта unknown call: dict/list и алиасы, ещё не прочитанные module globals, инициализацию Python до сценария и циклическую сериализацию. Нелитеральный default/module value без контекста теперь unknown, фабрика не попадает в scenario executes. Циклический исходящий body не даёт подтверждённого remote; циклический ответ не падает с RecursionError. Эти проверки включены в общий набор; полные init/codec semantics остаются вне среза.

В проверенном срезе FastAPI пересечения разных router/mount групп не упорядочиваются по файлам. Для одной группы в одном файле сохранён порядок деклараций. Консервативная инвалидация сохраняет final bindings Java; это не означает неизменяемости объектов по этим ссылкам. Неподдержанный static block не выдаёт вымышленный ноль. Итоговый сохранённый набор: 102 проверки.

Пятый этап проверил конфигурацию по deployment. Прежний глобальный regex смешивал значения сервисов, не понимал вложенный YAML, Unicode escapes и continuation properties. Нативные javaproperties/PyYAML и упорядоченные Environment snapshots теперь отделяют источники. Контрпримеры дополнительно выявили необходимость инвалидировать все property values при неизвестном Config Server, не игнорировать DispatcherServlet path в готовом snapshot, сохранять порядок активных профилей и отклонять неподдержанные includes/groups/cloud activation.

Разбор реального Java-кода обнаружил два других пропуска: enum_body_declarations скрывал методы перечислений, а DI выбирал Feign fallback как обычную реализацию успешного клиента. Методы enum теперь индексируются; proxy сохраняется, неподдержанный отказ с fallback остаётся диагностической границей.

Field Bean Validation проверяется до контроллера, но пользовательские class/getter/field callbacks, type-use constraints, executable validation и группы не выдаются за уже выполненную native-проверку. Длина String считается в UTF-16. Source exception handler добавляет executes собственного callback, без выдуманного calls от упавшего контроллера. При ревью исправлен также ручной oracle: исходный ControllerAdvice возвращает 400 и выполняет свой метод; предыдущий эталон 500 был неверен. Исправление делает старое предсказание неуспешным, история сохранена.

Мост дат использует явные clock/timezone и CPython/закреплённую IANA. Контрпримеры проверяют отрицательные миллисекунды, DST gap/overlap, выход за диапазон Python, nanoseconds и неизвестный HTTP codec. Неподдержанный ZoneId не превращается в придуманное Java-исключение: существуют допустимые Java fixed-offset/alias формы вне IANA-среза.

Текущий набор содержит 348 тестов. Все 8 публичных FastAPI HTTP-случаев и синтетические смешанные интеграции проходят; Java-корпус проходит 6/7 условных целей. Основная цепочка с непустыми коллекциями, Stream callbacks, конвертацией валют и записью статистики сохранена как провал. Это ограничения продукта, а не повод объявить переносимость доказанной. DeepSeek на этом этапе не дал содержательного ответа за 45 с; независимое ревью не засчитано.
