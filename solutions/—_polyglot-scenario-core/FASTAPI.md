# Нативные контракты Python и публичная HTTP-проверка

Вариант № 13 подключает исполняемый код FastAPI 0.143.3, Pydantic 2.14.1 / pydantic-core 2.50.1, PyJWT 2.15.1 и pwdlib 0.3.1. Разбор исследуемого Python остаётся в LibCST/AST и общем IR. Исследуемые модули, приложения, импорты и функции не исполняются Python-хостом. Нативные функции вызываются только из закреплённого allowlist доверенных библиотек. Исходная функция `default_factory` исполняется общим IR.

## Что взято из upstream

| Компонент | Исполняемая upstream-логика | Граница нашего адаптера |
| --- | --- | --- |
| FastAPI / Starlette | Сигнатуры и проверка OAuth2 form, `OAuth2PasswordBearer`, разбор заголовка и HTTPException | Передача исходного запроса и диагностик в IR; классы приложения не импортируются |
| Pydantic / pydantic-core | `create_model`, `Field`, `TypeAdapter`, validation, поля `model_fields_set`, конкретная JSON-сериализация | Построение схем из ограниченных исходных фактов, перенос значений в IR |
| PyJWT | Кодирование, подпись, binding аргументов, options и последовательность проверки claims | Три наследуемых temporal-hook получают явное время сценария; глобальной подмены часов нет |
| pwdlib / Argon2 / BCrypt | Проверка пароля, выбор hasher, проверка и обновление hash | Ресурсные пределы и непрозрачное представление нового случайного hash |

Четыре ключевых файла FastAPI, PyJWT и pwdlib побайтно совпали с официальными закреплёнными GitHub-тегами: [native-contracts.json](development/native-contracts.json). Установленные пакеты не изменялись. Полные уведомления и SHA-256 находятся в [third_party](third_party/provenance.json); окружение закреплено в [requirements.lock.txt](requirements.lock.txt).

При конфликте явно переданной версии с нативным контрактом анализ останавливает неподдержанный хвост. При отсутствии версии контракт предполагает проверенное окружение; определение версий всех исследуемых зависимостей по lock-файлам пока не реализовано. Версии библиотек анализатора входят в fingerprint и отчёт.

## Вход и состояние

Контекст может содержать `clock` — полный ISO instant с timezone, `globals` — известные значения после успешной инициализации приложения, `tables` — снимок строк. Произвольные инициализаторы приложения не воспроизводятся. Маршруты с префиксом из такой конфигурации извлекаются из исходников; имена приложения в ядро не вшиты.

JWT с активной временной проверкой требует `clock`. Текущее время компьютера не определяет результат анализа. Отсутствие времени, неизвестные криптографические аргументы и превышение ресурсных пределов останавливают наблюдаемый префикс; последующие методы не подтверждаются. Подпись и значения claims не выдумываются. Новый случайный password hash остаётся отдельным непустым символом; его реальные байты доступны только закрытому проверочному состоянию текущего пути. UUID также сохраняет символическую идентичность.

В пределах поддержанного подмножества Pydantic проверяет alias, ограничения, вложенные конкретные данные, extras, defaults и сериализацию. Исходные фабрики получают актуальный IR-движок, а не движок предыдущего сценария; фабрика с одним обязательным параметром получает upstream `validated_data`. Schema cache разделён по исходной конфигурации и не зависит от поздних runtime-записей глобальных переменных. Явно диагностируются пользовательские validators, serializers, lifecycle hooks, неподдержанные Field/config, рекурсивные схемы и сложная валидация абстрактных значений.

Простая зависимость `with Session(...) as value: yield value` сохраняет Session до конца запроса и закрывает её после него. Остальные генераторы не получают обещания точного teardown: состояние для следующего запроса инвалидируется. Это не полный FastAPI dependency lifecycle, streaming-response lifecycle или ASGI-runtime.

Внутренние вызовы конструкторов/`model_validate` Source-моделей в IR пока имеют более узкую семантику сборки полей, чем нативная проверка HTTP-тела и ответа. Полная повторная валидация экземпляров, assignment validation, ORM constraints, произвольные Python descriptors и все пользовательские hooks не реализованы. Успех перечисленных ниже трасс не доказывает правильность таких непроверенных путей.

## Публичный проект без Session/User-инъекции

Проверены неизменённые исходники [fastapi/full-stack-fastapi-template](https://github.com/fastapi/full-stack-fastapi-template/tree/b1125d8839482cb7bbae603ddc6d0081bf87532e), commit `b1125d8839482cb7bbae603ddc6d0081bf87532e`. Эталон [http_reference.json](development/http_reference.json) записан вручную до первого HTTP-прогноза; автор Codex, проверка не слепая. Это независимая от Train Ticket предметная область, но не независимый автор эталона.

На вход поданы HTTP-запросы, известная конфигурация после успешного startup, время и строки БД. Готовые `Session`, `User`, dependency results и рёбра не подаются. Основная цепочка: form login → password verification → исходное создание JWT → Bearer dependency → загрузка пользователя → создание/обновление/чтение/удаление item → 404 при следующем чтении. Проверены 13 executes, 5 calls, 6 data и пустой remote; все четыре набора сравнены с эталоном. Отдельные случаи: неверный пароль, неактивный пользователь, отсутствие Bearer, неверная подпись, истёкший токен, чужой owner, пустой title.

Все 8 случаев проходят. Каждый повторён отдельной `code/offline_run.py` CLI с hash seed 7 и 31. Совпадают графы, шаги, ответы, статус остановки и состояние. Проверяются перенос access token через историю, UUID и изменения полей, отсутствие private-полей в ответах. Хеши 25 производственных исходных файлов сохранены и после проверки совпадают. Runtime audit запрещает сеть и дочерние процессы. Запуски приложения и соединения с БД отсутствуют.

Воспроизведение после загрузки исходников указанного commit:

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B development/check_http_corpus.py \
  --source /path/to/full-stack-fastapi-template/backend \
  --output benchmark/public-http
```

[Результаты, входы и команды](benchmark/public-http/results.json) содержат отдельные измерения подготовки, анализа, полного процесса, RSS и нативных операций. `cold` и `repeat` здесь — два свежих процесса, а не демонстрация тёплого IR-cache. Модели не вызываются. Подготовка фиктивного password hash является подготовкой входных данных, не частью исследуемой трассы.

Эта проверка начинает с явных HTTP-запросов. Она не подтверждает полный путь от естественного языка и UI публичного проекта, а её remote-набор пуст. Смешанная Java → Python цепочка со всеми четырьмя непустыми отношениями проверяется отдельно синтетическим CLI; публичная Spring HTTP-цепочка, составные UI-запросы и повторно используемые summaries остаются работой общей цели.

В зафиксированном локальном прогоне основная семишаговая цепочка заняла 1,291 с всем процессом; подготовка 0,922 с, анализ 0,147 с, RSS 186318848 байт. Это единичное локальное измерение, не норматив. Общий набор содержит 286 тестов; [ревью изменений](development/phase4-review.json) фиксирует найденные дефекты и открытые работы.
