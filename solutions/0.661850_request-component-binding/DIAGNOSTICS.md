# Границы решения № 20

URL разбирается на независимые компоненты. Query хранит список вхождений каждого имени и признак полноты. Неизвестная неэкранированная строка может содержать `&`, `?`, `#` или `/`: она не становится «безопасным» сегментом, а неизвестное наличие параметра не превращается в его отсутствие. При неизвестном хвосте query путь сохраняется, но значения параметров могут остаться неизвестными из-за возможных повторов. Для переменной в query-шаблоне RestTemplate разделители кодируются внутри значения, поэтому соседние известные параметры сохраняются.

Поддержана передача UUID как символического текста без выдумывания конкретного идентификатора. Percent-последовательности декодируются один раз на HTTP-границе; `+` означает пробел только в query. Фрагмент не передаётся серверу. String-перегрузка RestTemplate использует ограниченную модель стандартного URI_COMPONENT с parsePath=true, включая повторное кодирование буквального `%`. Обнаруженные настройки URI template handler, encoding mode, parsePath и default URI variables делают результат неизвестным. URI-перегрузка, динамическая власть/порт, все варианты URI-синтаксиса и сторонние клиенты полностью не реализованы.

PathVariable, RequestParam и RequestHeader связываются по именам/alias из исходников. Различаются отсутствие, пустая строка и неизвестное значение; учитываются required, defaultValue и Optional. Поддержаны String, byte/short/int/long и их обёртки, boolean, char, UUID, простые List/Collection/ArrayList и массивы. Для чисел проверяется диапазон Java. Неизвестный пользовательский тип не вызывает выдуманного отказа. Форматтеры, InitBinder, конвертеры из текста и конфигурация MVC оставляют диагностику. Конвертер из собственного типа БД не считается конвертером HTTP-текста.

Полные query Map/MultiValueMap, enum/date/floating-point-конвертеры, настройки кодировки servlet-контейнера, form/multipart, наследуемые или динамически зарегистрированные конвертеры и сложные аннотации не покрыты. Matrix-параметры и закодированные разделители пути требуют политики сервера; конкретная привязка не утверждается. Правила выбора маршрута и регистрации фильтров унаследованы и остаются приближёнными.

При известном отказе named-value binding выполняются фильтры, дошедшие до диспетчера, и их продолжение после `chain.doFilter`. Обработчик не вызывается, ребро remote к нему не добавляется, его записи в БД отсутствуют. Нестандартный exception resolver оставляет HTTP-статус неизвестным. Полный граф собственных обработчиков ошибок не построен. Например, две проверки Petclinic подтверждают отказ до контроллера, но не конкретный итоговый статус.

Новая строгая привязка применяется к реконструированным межсервисным HTTP-запросам и явным wire-URL в проверках. Привязки действий естественного языка и браузерных форм по-прежнему используют унаследованный grounding. Это не полноценный сквозной HTTP/MVC-движок для всех действий интерфейса. Уже известные ограничения JSON-проекции, generic scalar binding, stream над Map view и выбора запросов не устранены этим изменением.

Проверки исходников Petclinic REST и PiggyMetrics охватывают выбор маршрута, аргументы и остановку до обработчика. Авторизация там задана как предпосылка. Цепочка Petclinic GET → PUT → GET проверяет тела контроллера/сервиса и доступ к данным; remote в ней пуст. Дополнительная цепочка склада проверяет непустые executes/calls/remote/data и состояние, но является синтетическим компонентом. Эти результаты не доказывают универсальную поддержку произвольного Spring-приложения.

Изменения проверялись на независимых контрактах до контрольного запуска Train Ticket. В построитель не добавлялись маршруты, поля, состояния или идентификаторы сценариев этого проекта. Открытый эталон S0 читает отдельная проверка после построения. После упаковки пользователь сообщил score сайта 0,661850 — без изменения относительно № 19; источник и точность сохранены в benchmark/site-score.json.
