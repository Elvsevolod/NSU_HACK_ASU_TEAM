## Что исправлено

Query хранит все вхождения и признак полноты. Отсутствие параметра отличается от неизвестного содержимого URL. Учитываются required, defaultValue для отсутствующего и пустого значения, Optional, коллекции и массивы. Проверяется диапазон целых Java, стандартные boolean/char/UUID-конверсии. Alias параметра берётся из исходника.

Разделены кодирование String-URL в RestTemplate и декодирование на стороне HTTP-получателя. Литералы и символические URL проходят одинаковую обработку; фрагмент не отправляется серверу. Неизвестная неэкранированная строка не считается безопасным сегментом. Ошибка отсутствующей URI-переменной возникает на стороне клиента до отправки.

Привязка аргументов выполняется после фильтров. При доказанном отказе обработчик не выполняется, remote к нему и его обращения к данным не появляются. Продолжение фильтра после `chain.doFilter` сохраняется. Для пользовательского обработчика ошибок конкретный HTTP-статус остаётся неизвестным. [Контракты Spring](checks/library-contracts.json), [границы реализации](DIAGNOSTICS.md).

## Воспроизводимость

Из каталога варианта, Python 3.11:

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py --source /path/to/project --skeleton /path/to/skeleton.json.gz --context /path/to/context --scenarios /path/to/scenarios --output /tmp/submission.json --report /tmp/analysis-report.json
.venv/bin/python -B code/verify_run.py --submission /tmp/submission.json --report /tmp/analysis-report.json --output /tmp/verification.json
PYTHONPATH=code .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
~~~

Для контрольного входа репозитория: `--source ../../tt-challenge/targets/trainticket`, `--skeleton ../../tt-challenge/skeleton/trainticket.json.gz`, `--context ../../tt-challenge/context`, `--scenarios ../../tt-challenge/scenarios`. Параметры: path-limit=4, constraints включены. Эталон читает отдельная проверка после построения. Offline-аудит не обнаружил сетевых обращений, дочерних процессов или чтения эталона.

Новые проверки воспроизводятся без запуска приложений:

~~~sh
PYTHONPATH=code python3 -B checks/check_request_graphs.py --code code --work /tmp/new-request-graph-work --output /tmp/request-graphs.json
PYTHONPATH=code python3 -B checks/check_request_projects.py --petclinic /path/to/petclinic-rest --piggymetrics /path/to/piggymetrics --work /tmp/new-public-project-work --output /tmp/public-projects.json
PYTHONPATH=code python3 -B checks/check_petclinic_graph.py --repository /path/to/petclinic-rest --work-dir /tmp/new-clinic-work --output /tmp/clinic.json
~~~

Коммиты исходников закреплены в результатах и проверены по SHA-256 файлов. Повторный запуск проверок требует нового рабочего каталога. Предсказатель не читает их эталоны и результаты.

[ZIP](solution.zip) содержит корневой `submission.json`, код, проверки, инструкции и компактные метрики. Полные диагностические отчёты, временные исходники проверок и логи не включаются в архив. Хеши членов — в `benchmark/package-manifest.json`; результаты проверки архива и повторного запуска сохраняются рядом с ним после упаковки.
