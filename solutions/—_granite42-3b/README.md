# Решение № 6.2 — granite42-3b

Родитель — № 6. Проверена замена парсера на **Granite 4.2-3B, 4 bit** (`ibm-granite/granite-4.2-3b-q4-mlx`). Полный прогон завершён. Существенного улучшения качества нет; дальнейшая доработка остановлена по условию пользователя. Оценка сайта не получена.

## Изменения

Локальный `mlx-lm`, нативный chat template с `enable_thinking=False`, ограничение JSON Schema через Outlines + **LLGuidance**, компактный JSON и дополнительная проверка `jsonschema`. Невалидные и обрезанные ответы не кэшируются. Контекст 8192 токена, вывод до 1800, seed 0, temperature 1.0, top_p 0.95, top_k 0, presence_penalty 0. Точные ревизии и хеши — в [манифесте](models-manifest.json), пакеты — в [requirements-lock.txt](requirements-lock.txt).

BGE-M3, инструкции модели и логика построения графа сохранены от № 6. Общий индекс совпадает по SHA-256 с № 6 и 6.1. Эмбеддер освобождается до загрузки парсера; локальные веса проверяются по SHA-256, `trust_remote_code=False`.

## Запуск

Из каталога варианта, на Mac с Apple Silicon:

```sh
python3.11 -m venv .venv
.venv/bin/pip install -r requirements-lock.txt
.venv/bin/python code/prepare_models.py --directory models
.venv/bin/python code/offline_run.py \
  --source ../../tt-challenge/targets/trainticket \
  --skeleton ../../tt-challenge/skeleton/trainticket.json.gz \
  --context ../../tt-challenge/context --scenarios ../../tt-challenge/scenarios \
  --model-manifest models/models.json --output submission.json \
  --report benchmark/analysis-report.json
```

Подготовка весов требует сети; анализ выполняется офлайн. Без `--index` индекс строится заново. Измеренный прогон использовал готовый общий индекс: [index-run.json](benchmark/index-run.json). ОС запрещала сеть и чтение эталона, образца и чужих ответов при построении результата; эталон читался отдельной проверкой после завершения.

## Ограничения и остановка

MLX требует Apple Silicon / Metal; `--cpu` отклоняется до чтения входа. Перенос исполнения на Linux и CPU не реализован. Ядро сохраняет ограничения № 6: Java/Spring и поддерживаемый фронтенд; адаптер Ktor не добавлялся. Корректный формат не доказывает точность или универсальность. Новые модельные прогоны, подбор промптов и дополнительные проверки переноса после отрицательного результата не запускались.

Реализация делегировалась DeepSeek через закреплённый OpenCode, изменения независимо проверены Codex. Последний дополнительный запрос получил rate limit; небольшие исправления завершены Codex. Данные — в [delegation.json](benchmark/delegation.json). Унаследованный `code/download_gguf.py` для этой модели не используется.
