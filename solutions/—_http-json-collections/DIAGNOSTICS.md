# Границы модели № 15

Анализатор прогнозирует выполнение по исходникам и предоставленному скелету. Он не запускает JVM, сервисы или внешнюю модель. Отчёт различает подтверждённые в пределах поддержанной модели рёбра и возможные рёбра; `partial` означает наличие существенных допущений. Успешная проверка JSON не доказывает точность графа.

Извлечение фактов находится в `analyzer/project.py` и `baseline_closure.py`; связь действий с запросами — в `analyzer/contracts.py` и модулях интерфейса; выполнение, значения и состояние — в `analyzer/engine.py`, `models.py`, `http_json.py`, `java_collections.py`. Бизнес-имена, константы и маршруты извлекаются из входов. Правил по идентификаторам сценариев в ядре нет.

## Что проверено отдельно

- Выбор виртуального метода по наблюдённому конструктору, ближайшее переопределение, границы static/private/super, доступ между пакетами. Канонические сигнатуры учитывают исходные импорты. Прямые переменные типов в сигнатурах и varargs не объявлены полностью поддержанными.
- Видимость типов по пакету, импортам и модулю. Одинаковый FQN в отдельных сервисах не делает собственный тип невидимым; посторонний класс из другого пакета не подменяет JDK-класс.
- ASCII-часть Integer.parseInt с radix 2–36 и границами int; гарантированные отказы завершают текущий путь. Unicode-цифры и неизвестные аргументы остаются неопределёнными.
- Отдельная идентичность сконструированных объектов и Map; копия состояния сохраняет идентичность исходного выделения. Совпадение полей не доказывает равенство ссылок. Сгенерированный UUID не заменяется выдуманными байтами.
- Map: put/get/containsKey/getOrDefault/remove/clear/putAll, поверхностное копирование, отличия String/Integer/Long/Boolean/Character/Byte/Short. Неподдержанное изменение сбрасывает содержимое. Представления entrySet/keySet/values, порядок обхода HashMap, произвольные объектные/null/float-ключи не моделируются точно.
- Узкие инициализаторы анонимного HashMap/LinkedHashMap: только блоки put без собственных полей и переопределений, с разрешимыми аргументами. Неподдержанные подклассы и неявные вызовы внешней области не превращаются в пустую карту. Отказ конструктора предшествует вычислению аргументов инициализатора.
- Простые числовые SQL-предикаты, AND, позиционные параметры, SQL NULL; сравнение строк по collation, JOIN и произвольные выражения SQL не объявлены поддержанными.
- Разделение Java-объекта, объявленной DTO-схемы, настоящих JSON-свойств и абстрактной JSON-строки. Служебное имя бизнес-поля не создаёт HTTP-ответ, Optional, Map, UUID или точный класс. Имена полей Java чувствительны к регистру.
- Запрос сериализуется и заново связывается с типом принимающей стороны. Сервисы не разделяют изменяемую карту, а JSON не сохраняет точный подкласс отправителя. Цикл в запросе останавливает отправку; цикл в ответе не запускает success-callback.
- Class, пустые ParameterizedTypeReference/TypeReference и ограниченный constructParametricType сохраняют описанный тип и место его объявления. Вложенные Map/List и простые параметры DTO подставляются с исходными импортами. Обобщённое наследование, wildcard/array-типы, произвольная рефлексия и конфигурация TypeFactory остаются границами поддержки.
- Обычный enum передаётся по имени константы; JsonValue/JsonFormat и другие настройки дают диагностику. UUID передаётся как текст с сохранением доказанной идентичности. Строка с JSON внутри не превращается в карту служебных полей.
- Тип исходного исключения берётся из наблюдённого класса, а не из поля __type__. Необработанный обычный отказ сервера переводится в HTTP-ошибку клиента; remote сохраняется, если контроллер действительно был вызван. Нестандартное разрешение исключений и неизвестный HTTP-статус оставляют альтернативы с предупреждением.

## Существенные ограничения

JSON-адаптер — ограниченная проекция полей, а не Jackson. Не выполняются все конструкторы, getter/setter, пользовательские сериализаторы, десериализаторы, обработчики исключений, регистрация бинов, security и bean validation. Публичные поля без дополнительных настроек проверены отдельно. Для non-public/transient полей, исходных и сгенерированных callback, Jackson-аннотаций и неизвестной политики лишних свойств выдаются предупреждения. Приблизительная проекция может дать неполный или неверный возможный граф; предупреждение не является доказательством его точности. Полный HTTP-граф Petclinic не измерен.

Поддержка Java остаётся ограниченной: не все приведения, исключения библиотек, числовые преобразования, смешанные return/throw при исчерпании бюджета, динамические методы и побочные эффекты JVM представлены полностью. В неизвестных ветвях используются альтернативы и консервативное замыкание; они могут добавлять лишние связи. Сброс спорного состояния может увеличивать неизвестность следующих запросов.

Языковое ранжирование запросов остаётся эвристическим. Примеры с фиксированным входным методом не оценивают понимание произвольного сценария. В тестах тел клиент и зависимости считаются предоставленными; полный жизненный цикл контейнера не воспроизводится. Отсутствие пути в исходном скелете и неподдержанные API не заменяются проектными правилами.

JavaScript анализируется в унаследованной ограниченной модели наблюдённых запросов и callback. Произвольные события, асинхронное расписание, мутации через алиасы, fetch/axios и Vue SFC не поддержаны полностью и диагностируются. Неизвестные данные пользователя нельзя восстановить из названий полей. Свидетель в checks/missing-input-witness.json объясняет отсутствие двух значений, но не все технические пропуски.

## Как читать измерения

`benchmark/mechanism-comparison.json` сравнивает одинаковые небольшие исходники и заранее зафиксированные вручную графы № 14 и № 15. Пустое отношение имеет IoU=null и не считается проверенным. Панель подобрана для диагностики механизмов; это не случайная выборка и не оценка точности на независимых больших приложениях.

`benchmark/coverage-summary.json` считает шаги с классами ограничений. Неизвестный receiver может быть следствием прежней потери значения; частоты не равны числу независимых дефектов и не измеряют precision/recall. `benchmark/input-coverage.json` считает явные Unknown input по всем альтернативам; свободные входные символы и доказанные генерации учитываются отдельно.

S0 проверяется отдельным процессом после построения ответа. Remote=1 в S0 — совпадение двух пустых множеств. Эталон не доступен построителю через offline_run.py; отдельный аудит фиксирует сетевые вызовы, дочерние процессы и обращения к эталону. Повтор ZIP проверяет воспроизводимость, а не скрытую точность.
