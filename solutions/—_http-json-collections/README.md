Пустое отношение имеет IoU=null. Панель диагностическая и подобрана по механизмам; её нельзя трактовать как оценку точности на новых больших проектах. Один путь интерфейса включает выбор запроса по тексту; остальные фиксируют входной метод и проверяют выполнение при заданных зависимостях.

Устранены выбор лишних реализаций при известном конструкторе, неверное продолжение после parseInt, смешение ссылок и содержимого Map, потеря копии инициализированной коллекции, неверные SQL-сравнения и обход границы HTTP. У объектов и JSON разделены бизнес-поля и сведения анализатора. Запросы копируются и декодируются по принимающей схеме, точный подкласс отправителя не переносится. Сохраняются вложенные типы Class/ParameterizedTypeReference/TypeReference и ограниченного TypeFactory с импортами места использования. Enum, UUID и JSON-строки не превращаются в карты служебных полей. Исправлены чувствительность имён полей к регистру, типы catch и передача отказов сервера клиенту.

## Что остаётся слабым

[Сводка покрытия](benchmark/coverage-summary.json) отделяет неизвестный receiver, неразрешённый внешний тип, модель объекта, метод исходного класса и неподдержанную операцию. Эти частоты не равны точности отношений и не являются независимыми дефектами: одна потеря значения распространяется по цепочке.

Главные открытые границы — жизненный цикл JSON/JavaBeans и фреймворка, представления и обход коллекций, дальнейший перенос неопределённого состояния, языковой выбор API и часть браузерных эффектов. Getter/setter, пользовательские codecs/exception resolvers, регистрация бинов, security, validation, сложные generics и полный JavaScript не воспроизводятся полностью. Они явно ограничивают результат. Подробности и определения — в [DIAGNOSTICS.md](DIAGNOSTICS.md).

[Аудит входов](benchmark/input-coverage.json) сохраняет каждый пропуск по всем альтернативам. Свободный символ не выдаётся за конкретные данные. Старый [свидетель отсутствующих значений](checks/missing-input-witness.json) объясняет две неоднозначности, а не все технические пропуски. Цель устранить все неизвестные входы остаётся открытой.

## Независимые проверки и воспроизведение

Проходят цепочки склада, библиотеки и двух сервисов с записью данных; одинаковые FQN разрешаются внутри своего модуля. На 78 реальных Java-файлах Petclinic REST v2.1.5 повторены [11 проб выбора и маршрутизации](benchmark/petclinic.json) и [ограниченная цепочка GET → PUT → GET](benchmark/petclinic-body-graph.json): executes/calls/data IoU=1, изменение состояния сохраняется. Это тела методов при заданных preconditions. Полный HTTP/security/validation/Jackson-граф другого реального приложения отсутствует; remote в Petclinic пуст.
