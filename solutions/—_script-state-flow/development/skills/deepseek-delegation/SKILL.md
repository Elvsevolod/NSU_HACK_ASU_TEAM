# Делегирование задач DeepSeek

**Ты, Codex, управляешь задачей и обязательно самостоятельно делаешь код-ревью решения DeepSeek.** DeepSeek выполняет порученную разработку; ответственность за проверку, приёмку и итоговый ответ остаётся у тебя. Его сообщение «готово» и его собственное ревью не заменяют твою проверку.

## Среда

- Запускай установленный `~/.local/bin/opencode-deepseek`. Этот локальный запускатель закрепляет модель и её параметры, в том числе при конфликтующих настройках проекта.
- Используй только `opencode/deepseek-v4.1-flash-free`, рассуждение `max`, включая служебные обращения. При недоступности сервиса сообщи об этом; не переходи на другую или платную модель.
- В OpenCode уже настроены глобальный `~/.config/opencode/AGENTS.md`, автоматическое подключение полного `~/.agents/skills/karpathy-guidelines/SKILL.md` через `instructions` и MCP `context7`/`gh_grep`. Перед первой правкой в новой сессии должен успешно выполняться нативный `skill` с именем `karpathy-guidelines`. Проверяй это по журналу, а не по обещанию исполнителя. Напоминание о навыке в каждом задании не требуется.
- При сомнениях в API и библиотеках используй актуальную документацию Context7. Не отправляй приватные исходники и данные проекта в публичный поиск `gh_grep`.

## Постановка задачи

Прочитай применимые AGENTS.md и нужные исходники. Зафиксируй исходное состояние разрешённых файлов: в Git учти уже существующие изменения пользователя; без Git сохрани снимок этих файлов. Это нужно, чтобы отличить изменения DeepSeek от прежней работы.

Передавай ограниченную задачу с проверяемым результатом. В поручении укажи:

- абсолютный рабочий каталог, нужные файлы и контекст;
- требуемое поведение, существенные пограничные случаи и критерии приёмки;
- какие файлы можно менять и что требуется сохранить;
- команды релевантных проверок и требуемый отчёт: изменения, фактические результаты, оставшиеся проблемы.

Для сложной работы сначала выдели самостоятельный этап. Не поручай одновременно исполнителям изменение одних и тех же файлов. Не расширяй задачу до соседнего рефакторинга.

## Запуск и контроль

Передай текст задания отдельным аргументом процесса. Пример аргументов для запуска через `subprocess` без `shell=True`:

```python
args = [
    str(Path.home() / ".local/bin/opencode-deepseek"),
    "run", "--dir", str(project_dir),
    "--format", "json", "--agent", "build", "--variant", "max",
    task_text,
]
```

Здесь `project_dir` — абсолютный каталог задачи; `task_text` — подготовленное поручение. Сохраняй stdout непосредственно в файл JSONL, stderr — отдельно. JSONL содержит отдельное событие на строку, а не один общий JSON. Сохрани `sessionID` для продолжения. Для замечаний передавай тот же `--dir` и `--session SESSION_ID`; не используй неоднозначное продолжение последней сессии.

По умолчанию OpenCode запрашивает разрешение на правки и shell-команды. В неинтерактивном запуске такой запрос может завершиться отказом. Если действие уже разрешено текущей задачей пользователя, передай разрешения только этому процессу через `OPENCODE_PERMISSION`: запрети остальные правки и команды, разреши конкретные файлы и нужные команды проверки. Не меняй ради этого глобальные разрешения. Запрещённые пользователем действия таким способом не разрешай.

Шаблоны `edit` в установленной версии сопоставляются с путём относительно worktree OpenCode. Одного имени файла или абсолютного пути может быть недостаточно. При отказе выясни фактический путь и исправь узкий шаблон; не обходи отказ записью через shell и не разрешай все пути. Не используй глобальное автоматическое одобрение.

Проверяй события `error`, статусы `tool_use`, вывод проверок и фактический дифф. Успешный код завершения процесса сам по себе не означает, что задача решена. Для продолжительного запуска сохраняй возможность сообщать пользователю о ходе работы; не оставляй зависший процесс без контроля. Если повторная попытка не даёт прогресса, разбери причину или сообщи о блокировке вместо бесконечных перезапусков.

## Обязательное код-ревью со стороны Codex

После ответа DeepSeek самостоятельно:

1. Прочитай весь его дифф относительно сохранённого состояния. Убедись, что изменения относятся к заданию, разрешённым файлам и не затрагивают работу пользователя.
2. Проверь логику по контракту задачи: обычные и пограничные случаи, обработку ошибок, побочные эффекты, совместимость с окружающим кодом. Оцени сложность, зависимости и риски в затронутых местах; убери избыточность через конкретные замечания.
3. Проверь сами тесты: они не должны быть ослаблены, подменять результат или только повторять реализацию. Самостоятельно выполни релевантные проверки; для нетривиальной логики добавь независимые сценарии. Для небольших правок достаточно соразмерной проверки реального поведения.
4. Сопоставь фактический результат с заявлением исполнителя. Проверь, что он действительно загрузил Karpathy Guidelines до правок, соблюдал AGENTS.md и не скрыл ошибки инструментов или пропущенные проверки. При необходимости проверь модель, `variant=max` и стоимость через экспорт сессии.

При дефекте передай в ту же сессию конкретное замечание с местом, воспроизведением и ожидаемым поведением. Попроси минимальное исправление; для ошибки логики — воспроизводящий тест. После исправления снова просмотри дифф и выполни затронутые проверки. Не принимай решение, пока существенные замечания не устранены; если проверка недоступна, явно укажи, что осталось неподтверждённым.

## Правила NSU_HACK_ASU_TEAM

Навык применяется из корня проекта, где расположены `tt-challenge/`, `sample/`, `solutions/` и `skills/`.

- При создании варианта решения или записи бенчмарка сначала прочитай [solution-versions](../solution-versions/SKILL.md) и передай исполнителю относящиеся к задаче правила.
- Сохраняй ограничения проектного AGENTS.md: `tt-challenge/`, `sample/` и прежние `runs/` доступны только для чтения; Train Ticket и его сервисы не запускать. Существующие варианты и работу участников не перезаписывать.
- DeepSeek используется для разработки. Готовое решение остаётся на Python без внешних LLM API. Эталон допустим в проверке, но не в построителе ответа; не добавляй поведение по идентификаторам S0–S7.

## Завершение

Итог пользователю подводит Codex: что реализовал DeepSeek, что ты проверил при код-ревью, какие проверки сам выполнил и какие ограничения остались. Задача завершена после твоей приёмки, а не после ответа исполнителя. Делегирование не даёт отдельного разрешения на публикацию, отправку решения или изменение внешних систем.
