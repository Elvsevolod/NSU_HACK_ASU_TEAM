# Диагностика № 14

## Новая граница script-state-flow

633 теста проходят. Перенос наблюдённых ответов через обычные var проверен отдельно от интерпретации сценариев. Два новых примера сравнивают весь вручную перечисленный граф синтетической цепочки двух сервисов: executes/calls/remote/data, включая непустой remote, и меняют ветвь при изменении количества в таблице. Это не эталон реального приложения. Все восемь графов Train Ticket совпадают с № 12; неизвестных по-прежнему 18 шагов и 40 пар шаг–поле.

Нужны уникальное объявление var, единственная доказанная HTML-страница скрипта и закрытая модель подключённых классических скриптов. Поддержаны только безопасный литеральный префикс и простые записи в реально обработанном success. Произвольные вызовы с эффектами, динамический this, алиасы, записи вне этого callback, глобальный объект, неизвестные подключения, несколько страниц, модули и inline-код блокируют точное значение с диагностикой. Сложные области видимости (destructuring/default/rest, class, import/export/eval/with) отключают этот срез. Это консервативные отказы от поддержки, не полная модель JavaScript.

Неизвестная условная запись не сохраняет старое известное значение. Глобальные чтения разрешаются в исходном AST с учётом теней; callback не получает старую копию глобального значения из параметров предыдущего запроса. Переменные хранятся отдельно по страницам и сценариям. После утраты страницы даже позднее обращение к ещё одной переменной не восстанавливает её литеральный default. HTTP-ответ копируется, поэтому серверная мутация объекта не меняет браузерный снимок.

Обнаруженные при собственном ревью случаи alias/opaque-call/this, раннего выхода, недостижимой записи, нескольких страниц и утраты страницы проверены отдельными отрицательными примерами. Это ограниченный набор контрпримеров, не доказательство отсутствия других дефектов. __proto__ исключён из безопасных объектных литералов по подтверждённому замечанию DeepSeek. Его замечания о named function expression и block function проверены и отклонены: соответствующие тени/коллизии уже не разрешались как глобальные.

Комментарии между Vue-методами больше не отключают чистые уравнения. Незнакомые объявления component options, в частности mounted в кратком синтаксисе, по-прежнему не моделируются и теперь имеют явную диагностику. Поэтому эта правка не устранила оставшиеся потери selected-row/oldTripId в Train Ticket. Структурная поддержка скриптов сама по себе не восстанавливает выполнение UI-событий или сериализацию Java Map; произвольное поле __map__ не распаковывается по одному имени.

Ниже сохранена диагностика унаследованной семантики № 11–12 и оставшихся входов. Её ограничения относятся и к № 14.

Нулевая цель не достигнута: 18 шагов и 40 пар шаг–поле остаются неизвестными. У № 11 по тому же аудиту — 18 и 49. Все альтернативы проверены; шагов без запроса нет. Все восемь сценариев partial. Счётчик не включает конкретные байты UUID и отдельно учтённые свободные символические входы.

## Проверенная корректность

Из № 11 сохранены регрессии всех семи замечаний ревью № 10: HTTP-метод, остановка после отказа, switch/catch, UUID, единицы и форматирование, MySQL, контекст сценария; также Profile, int и законный каталог sample. Новые тесты проверяют порядок DOM-записей, text/val, callback и лексические тени, ложные UI-условия и source select, неизвестные ветви, исходный HTML5-текст и перенос достоверности состояния. 633 теста проходят.

Ключевой новый контрпример: неподтверждённая подготовка первого запроса сохраняет enabled=true, следующий запрос читает запись и вызывает approved(). Ранее это давало confirmed. Теперь предположение наследуется и рёбра остаются possible. Неизвестный запрос также помечает последующее состояние; при объединении сохраняются предупреждения всех альтернатив. Механизм намеренно грубый: не выполняет причинный анализ отдельных полей, не снимает предположения после полной перезаписи и может понижать достоверность независимых рёбер. Полной семантической корректности Java он не доказывает.

## Граница браузера

Поддержана узкая модель литеральных jQuery DOM-записей в лексических окнах перед запросом. Записи из независимого обработчика не считаются исполненными по имени. Callback, plugin и пользовательская подготовка остаются гипотезами. Переменные, захваченные из внешнего окна, консервативно неизвестны; изменяемый ввод перед modal не считается окончательным значением. Динамические/алиасные/native DOM-писатели, некоторые циклы, HTML-замены и неоднозначные селекторы ограничивают поддержку и диагностируются.

Текст option сохраняет исходные пробелы. Поэтому indexOf как условие может выбирать неожиданную ветвь исходного приложения; исправлять намерение его автора анализатор не должен. Скрытый элемент сохраняет textContent. Отрицательный выбор в тексте сценария не доказывает очистку сводки. Несколько исходных HTTP-запросов одного действия видны как граница: их полное последовательное расписание пока не моделируется.

Числа JavaScript, ToPrimitive, события и DOM поддержаны не полностью. Для неразрешённой версии jQuery text(null) неизвестен: в локальном jQuery 2.0.3 используется createTextNode, а в [исходнике jQuery 3.5.1](https://github.com/jquery/jquery/blob/3.5.1/src/manipulation.js) — textContent. Правила [val(null/undefined)](https://github.com/jquery/jquery/blob/3.5.1/src/attributes/val.js) и text различаются. text(undefined) не записывает новое содержимое. Возвращаемое значение setter не принимается за getter. UTF16 длина/indexOf поддержаны; некоторые операции по отдельным суррогатам возвращают Unknown. Рост DOM-выражений ограничен и диагностируется.
