# Local code-model runtime audit before inference

Direct user approval covers local UniXcoder, CodeT5+ 110M embedding and CodeRankEmbed weights/runtime. The three downloaded weight SHA256 values match their pinned Hub LFS records. No model forward has been performed at this checkpoint.

- UniXcoder: microsoft/unixcoder-base@5604afdc964f6c53782a6813140ade5216b99006, card Apache-2.0. Stock Roberta architecture. Official Microsoft/CodeBERT wrapper pinned at c0de43d3aaf38e89290f1efb771f8de845e7a489; wrapper MIT. Its encoder-only tokenizer prepends CLS, `<encoder-only>`, SEP and appends SEP, cuts to max_length-4, uses a bidirectional 3D non-pad mask despite is_decoder=True, masked mean and L2 normalization for cosine. No decoder/generation path is required or executed. Java is among the code-search languages; English NL training does not establish Russian quality. Physical max_position_embeddings=1026; official wrapper requires max_length<1024. Pilot cap512.
- CodeT5+: Salesforce/codet5p-110m-embedding@d9f3a534af4252f04b10cd9f78e05037542d10f6, card BSD-3-Clause. Both Python files were read fully: configuration fields plus a stock T5EncoderModel with trained Linear(768,256), first encoder token, then F.normalize. A local adapter reproduces that forward with stock T5Config/T5EncoderModel; it never calls AutoModel/trust_remote_code. Projection weights must load as strictly as encoder weights. The card lists nine programming languages including Java; config n_positions512. This is an embedding checkpoint, not a generative code planner.
- CodeRank: nomic-ai/CodeRankEmbed@3c4b60807d71f79b43f3c4363786d9493691f8b1, card MIT; 137M bi-encoder, card context8192, code retrieval. All 1217 modeling lines and 55 configuration lines reviewed. Imports are standard library, PyTorch, einops, safetensors and pinned Transformers. Forward is explicit tensor attention/rotary/MLP; no FlashAttention extension import or target-code execution. The custom from_pretrained/state_dict_from_pretrained helpers contain optional Hub lookup and unrestricted torch.load paths; the pilot does not call them. It instantiates the audited local NomicBertConfig/NomicBertModel and strictly loads local safetensors instead. The checkpoint's sentence-transformers modules prescribe CLS pooling, not mean; cosine comparison adds L2 normalization. Queries use the card prefix `Represent this query for searching relevant code: `; documents do not. No blanket Russian-language capability claim is made.

Common controls: model files pinned and hashed, native tokenizer local_files_only and trust_remote_code=False; tensor-only torch.load(weights_only=True) for the two legacy .bin files; CodeRank safetensors. No model-supplied download method, dynamic remote import, subprocess, target Java/JS execution, or external API is permitted during inference. Reviewed custom source bytes are stored under development/model-code and checked against the metadata hashes before import. Every required tensor must load; a mismatch is a runtime failure, not silently random projection weights.

Existing approved torch2.9.0/transformers4.57.1/tokenizers0.22.1/ST5.1.2 runtime is reused read-only. Only einops0.8.1 is added in a separate overlay directory; its wheel SHA256 is checked against official PyPI metadata, with offline --no-deps installation. Original №32 runtime files are not modified. First smoke may still uncover compatibility failures; this audit is not an inference or quality measurement.

Active frozen pilot is development/model-pilot/frozen-v2. Original frozen/ is a pre-inference design draft, retained. Every embedding sees identical candidate IDs and method/contract text; 32 familiar development queries and 16 new licensing-domain test queries are separate. The two familiar real projects are development after their earlier failures. The licensing source was previously read for eligibility but no analyzer/model inference on it was used for labels; public pretraining overlap is unknown. It is a retrieval holdout, not a full semantic execution oracle.
