# Границы варианта №33

E21 history constraint ограничен прямым singular GET, одним PathVariable и явной английской prior-creation ссылкой. Проверяются source/native type, два completed producer digest и actual response field. Это не общий NL/compound planner и не модельная калибровка. [Доказательства и границы](development/IMPLEMENTATION_E21.md). [Source preflight default404](development/missing-route-preflight/DECISION.md): HTTP404/body не выдуманы.

E16 literal-body support ограничен одним завершающим JSON-объектом после `:`/`=` для прямого source RequestBody. UI, несколько тел, field-labelled объекты, duplicate keys и non-finite numbers явно отклоняются; поддержка всех JSON/Jackson форм не заявлена. Незаданные заголовки не становятся известными.

Анализатор получает готовый граф-скелет. Его рёбра остаются may-фактами: source receiver constraints отбрасывают доказанно несовместимые targets, но не заменяют полное разрешение типов, Spring DI, proxy/AOP или регистрацию bean. Отсутствие аннотаций у plain mapped class в известном Boot deployment позволяет исключить этот ложный handler; произвольные meta-annotations и scan rules не считаются полностью поддержанными.

Deployment выбирается по точному имени модуля или declared deployment unit. Относительный URL с несколькими units остаётся неоднозначным. Module substring не служит alias. Explicit HTTP поддерживает проверенные заголовки и JSON body; это не общий HTTP parser всех MIME/transport режимов.

Конфигурация использует `config_entry` факты графа с module/file/doc либо явно supplied `context.configuration[module].propertySources` в порядке от сильного к слабому. Общая идея перенесена из №13 в текущий IR. Парсинг YAML/properties с нуля остаётся обязанностью extraction adapter; полный Spring Environment, OS environment, Config Server, ConfigData imports/groups и версия каждого bootstrap-механизма не реализованы. Неизвестный внешний environment не доказывает локальный context path. Profile expression поддерживается в простом проверенном subset; сложный остаётся unknown.

Неизвестные результаты стандартных repository List/ArrayList/LinkedList/Set/HashSet/Collection сохраняют non-null контейнер, а не конкретные элементы и размер. Source/default method может вернуть null. Абстрактные Set/Collection не подтверждают конкретный runtime class или произвольные операции; cast/mutation без контракта останавливаются. Это не полная коллекционная модель Spring Data.

Jackson `JsonProperty` поддержан в bean lifecycle для literal name, AUTO/READ_ONLY/WRITE_ONLY/READ_WRITE и проверенных полей, getters/setters, inheritance и Lombok. Внешнее JSON-имя отделено от Java storage; JSON access не отключает обычный Java setter. required/defaultValue не становятся проверкой обязательности или подставленным значением. Creator parameters, symbolic annotation constants, index и READ_ONLY с переименованием при неизвестном контракте версии остаются границами. Полный Jackson, отражение final fields и произвольные generated annotation-copying rules не реализованы. Feign response теперь использует bean lifecycle, включая source callbacks, порядок и DecodeException. Это bounded default Spring/Jackson path; custom codecs, unobserved registration и неподтверждённые override policies не подменяются стандартным codec.

Feign принимает доказанную стандартную аннотацию, literal name/value/path и explicit URL с доказанными placeholders calling module. Проверены стандартные PathVariable/RequestParam/RequestHeader, encoding и native EXPLODED finite List query. Неизвестные placeholders, alias conflicts, config-only URL override с ненаблюдаемой policy, QueryMap, custom converters, nondefault collection formats и unbounded collections остаются границами. E6 source RequestInterceptor исполняется в доказанном default Boot scan: Component или ограниченная noarg Bean factory, literal/Value fields, scenario-local state и альтернативы порядка. Header/removeHeader проверены по Feign 10.10.1. Неподдержанные registration/lifecycle/template operations останавливают dispatch. Mixed OAuth/source ordering, произвольный Spring container и SecurityFilterChain не заявлены. Default Feign error message сохраняется как native String с transport origin; exact bytes и подкласс исключения не выдумываются. Custom ErrorDecoder и Retry-After policies требуют отдельного контракта.

Computed static вычисляется в поддержанном source subset. `String.getBytes()` без наблюдаемой default charset не приравнивается ASCII или UTF‑8. Можно явно передать `java_default_charset` (совместим прежний ключ `charset`) в анализируемом контексте либо указать charset в исходном вызове. Стандартные charset-операции и basic Base64 ограничены проверенными случаями; malformed UTF‑16 replacement, произвольные charset и Java array creation не объявляются реализованными. Типизированный byte[] может быть передан как adapter input. [Контракт JDK](https://docs.oracle.com/javase/8/docs/api/java/lang/String.html#getBytes--) использует default charset платформы, а не скрыто выбранную анализатором кодировку.

Пилоты моделей проверены на Apple M4 Pro, 24 ГиБ, macOS 15.7.3, Python 3.11.9, MPS, fp32, 4 CPU threads. CPU throughput и другие машины не измерены. Fresh process не означает очищенный OS page cache. Приведённый RSS относится к процессу, MPS allocated/driver memory записаны отдельно и не складываются с ним как независимые физические области.

Модель ранжирует существующие IDs. Она не создаёт аргументы, permissions, токены, SQL state, completion или рёбра. Экспериментальный CodeRank adapter находится в checks, не в default pipeline. Его source index проверяет source/config fingerprint и canonical text. Стандартный немодельный режим и explicit bypass работают без весов. Production snapshot fallback проверен на отсутствие модели, corrupt files, revision/source mismatch и чужие IDs. Пилотный embedding cache не равен production snapshot и не является самостоятельным сертификатом целостности.

Organization/library имеют частичные source oracle. Их required coverage не даёт precision или full IoU. Licensing — новый retrieval test, не полноценная semantic/state проверка. Публичное пересечение с pretraining неизвестно. После текущих результатов все эти данные считаются известными для следующего tuning.

В исходном TT контексте JJWT login упирается в ненаблюдаемый clock. Отдельный контроль с явно заданными clock/charset проходит login→contacts и использует фактический `result.data.userId`; эти runtime inputs не приписываются исходному S0. У client UI сохраняется guard, у выбранного admin callback другая storage lineage. Не доказан новый дефект DB и не заявлено прохождение source-faithful frontend.

Открытый S0 не заменяет скрытые S1–S7. Предсказанные дельты №32→33 не считаются исправлениями hidden gold. Полная переносимость на независимые проекты и другие стеки не подтверждена.

Новые employment/healthcare expectations заморожены до первых предсказаний. Они описывают выбранные service slices при supplied resolved configuration, отключённом Spring AOP и open-in-view, здоровом datastore без внешних writers. Это отдельный тестовый deployment, не доказательство работы fallback/AOP в исходной production конфигурации. Source review выполнен Codex; второго независимого автора нет. Generated Long IDs заданы отношениями свежести и producer identity, без удобных чисел. Error timestamp и version-dependent Feign message bytes не объявляются точными константами.

E7 переносит proven non-null Java byte/short/int/long symbols как canonical decimal String и восстанавливает исходное значение в default Spring named-value binder того же разряда. E8–E14 используют такой carrier в составном URI и Java String concat/source exception message. Конкретный generated ID не выбирается. Narrowing/widening, opaque String, nullable boxed identity и source namesake не подтверждают корректную decimal conversion.

Lombok builder ограничен доказанной native class-level аннотацией и default generated all-args construction. Source builder method имеет приоритет. Разрешён отдельный source constructor другой арности при доказанном native AllArgsConstructor: его body не запускается вместо generated all-args. Custom builder class/method policy, source all-args selection, initializer effects, generic/inherited DTO, Builder.Default, Singular и NonNull остаются границами.

E14 typed transport checker покрывает каждый alternative graph/state, внешний wire, порядок remote requests, encoded remote responses, native Long bindings, ordered SQL и history/error origin. Это source-engineered development extension после просмотра первых результатов, не новый untouched holdout. Healthcare explicit11/11 и employment10/11 не означают полный NL transfer. Default absent-handler dispatch пока неизвестен даже для существующего source сервиса; неизвестный host тем более не превращается в выдуманный HTTP404.

На новых40 retrieval queries CodeRank улучшает ranking, но старые calibrated thresholds дают accept0/40 у него и общего BM25. Пороги не подгонялись по test. Все эти данные после измерения считаются development; отдельный downstream model run на новых двух приложениях пока не выполнен. Модель в default не добавлена, reranker и обучение не запускались.
