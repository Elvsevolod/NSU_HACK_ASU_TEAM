# Решение № 6.1 — qwen35-9b

Родитель — № 6. Проверена замена парсера на **Qwen3.5-9B, 4 bit** (`mlx-community/Qwen3.5-9B-4bit`, текстовая часть). Полный прогон завершён, убедительного улучшения качества нет. Оценка сайта не получена.

## Изменения

Локальный `mlx-lm`, нативный chat template с `enable_thinking=False`, ограничение JSON Schema через Outlines + **LLGuidance** и дополнительная проверка `jsonschema`. Компактный JSON предотвращает расход бюджета на пробелы между полями; обрезанные и невалидные ответы не кэшируются. Контекст 8192 токена, вывод до 1800, seed 0, temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5 с окном 20 токенов. Точные ревизии и хеши файлов — в [манифесте](models-manifest.json), пакеты — в [requirements-lock.txt](requirements-lock.txt).

BGE-M3, индекс, инструкции модели и логика построения графа сохранены от № 6. Эмбеддер освобождается до загрузки парсера. Локальные веса проверяются по SHA-256, `trust_remote_code=False`.

## Запуск

Из каталога варианта, на Mac с Apple Silicon:

```sh
python3.11 -m venv .venv
.venv/bin/pip install -r requirements-lock.txt
.venv/bin/python code/prepare_models.py --directory models
.venv/bin/python code/offline_run.py \
  --source ../../tt-challenge/targets/trainticket \
  --skeleton ../../tt-challenge/skeleton/trainticket.json.gz \
  --context ../../tt-challenge/context --scenarios ../../tt-challenge/scenarios \
  --model-manifest models/models.json --output submission.json \
  --report benchmark/analysis-report.json
```

Подготовка весов требует сети; анализ выполняется офлайн. Без `--index` индекс строится заново. Измеренный прогон использовал готовый общий индекс; его хеш — в [index-run.json](benchmark/index-run.json). ОС запрещала сеть и чтение эталона, образца и чужих ответов при построении результата; эталон читался отдельной проверкой после завершения.

## Ограничения

MLX требует Apple Silicon / Metal; `--cpu` отклоняется до чтения входа. Перенос на Linux и CPU не реализован. Ядро сохраняет ограничения № 6: Java/Spring и поддерживаемый фронтенд; адаптер Ktor не добавлялся. Точность скрытых S1–S7 неизвестна. После слабого результата повторный модельный прогон и новые проверки переноса не запускались.

Реализация делегировалась DeepSeek через закреплённый OpenCode, изменения независимо проверены Codex. Последний дополнительный запрос получил rate limit; небольшие исправления завершены Codex. Данные — в [delegation.json](benchmark/delegation.json). Унаследованный `code/download_gguf.py` для этой модели не используется.
