# Границы варианта № 18

Изменения относятся к исходным фактам Java и ограниченному связыванию HTTP/JSON. Поведение не зависит от бизнес-имён, маршрутов и идентификаторов сценариев. Старые ограничения коллекций, браузера, ORM, отказов и жизненного цикла Spring сохраняются.

## Что добавлено

Параметры классов/интерфейсов, верхние границы, superclass и полный список superinterfaces извлекаются из AST. Текст строк и комментариев в аннотациях не становится отношением наследования. Аннотация перед параметром типа не подменяет его имя; это относится и к параметрам методов.

В JSON-декодере параметр типа хранит место использования и окружающую подстановку. Для унаследованного поля подстановки составляются по единственному исходному пути к объявившему поле типу. Проверены несколько уровней наследования, вложенные Map/List, переставленные аргументы, одинаковые имена параметров и разные пространства имён. Аргумент не заимствует imports из класса, который его принимает.

Для raw-типа используется объявленная левая верхняя граница, включая зависимости между параметрами и ограниченные рекурсивные случаи. Отсутствующая граница — java.lang.Object. Имя параметра String не доказывает класс java.lang.String. Нативные классы различаются с одноимёнными классами исследуемого проекта. Кешируются только исходные пути наследования; значения, состояния и подстановки отдельных объектов туда не попадают.

Циклическое/неоднозначное наследование, неверная арность, wildcard и неподдержанные типы оставляют диагностированную неопределённость. Обход ограничен 64 уровнями и 4096 посещениями; превышение не создаёт доказанного типа. Это бюджет анализа, а не численный критерий качества продукта.

## Защита границы JSON

Необъявленное JSON-свойство не создаёт поле Java. Если политика неизвестна, объект остаётся неизвестным. Для явно доказанного нативного @JsonIgnoreProperties(ignoreUnknown=true) неизвестные свойства отбрасываются. Буквальное true извлекается из AST; комментарий, строка, false и внешняя одноимённая аннотация не включают эту политику. Другие эффекты Jackson-аннотаций и жизненного цикла по-прежнему диагностируются; полная поддержка аннотации не заявляется.

Абстрактный класс, интерфейс, local class и нестатический member class не превращаются в готовый экземпляр при отсутствии поддержанного конструктора/адаптера. Обычный static member и неявно static member интерфейса проверены отдельно. Это ограничение десериализации; наличие абстрактного предка у конкретного DTO не запрещает связывание его полей.

JSON null для примитива не моделируется как допустимая Java-ссылка null и не подменяется произвольным нулём. Без доказанной политики codec/default/failure поле получает неопределённость с предупреждением. Null для boxed-типа и generic-ссылки остаётся null; для него создание экземпляра не требуется. Полные конфигурации ObjectMapper и Spring codec пока не моделируются.

## Что остаётся открытым

Подстановка в JSON-схеме не реализует полную Java-подстановку возвращаемых типов, runtime checkcast, overload resolution или произвольное сохранение boxed-класса скаляра. Предыдущий пример generic-параметра String и stream над Map view остаются неполными и включены в панель как ограничения. Поддержка всех generics/JVM не заявляется.

Custom codecs, polymorphism, JavaBeans, constructor/creator callbacks, глобальные настройки mapper, валидация, безопасность и Spring interception покрыты частично. Вложенные owner-generics, wildcard/array-контракты и некоторые generic-bounds требуют дальнейшей модели. Для неподдержанного случая диагностика не означает точного предсказания исключения или всех последующих связей.

Неизвестная длина списков при heap join, equals/hashCode исходных объектов, полный порядок/контракты всех Collections и JS-эффекты сохраняют границы № 17. Полного эталона HTTP/security/Jackson другого реального приложения пока нет.

## Как проверялось

Панель содержит 45 компонентов и 40 семейств. Исходники и вручную заданные ссылки фиксируются до предсказания, совпадают для № 17/18. Точных графов — 38 → 43; два старых ограничения остаются. Непустые отношения проверяются отдельно, пустые не считаются качеством 1. Подборка не является репрезентативной оценкой переносимости.

В проверке Petclinic исправлен вход самой фикстуры: тело PUT содержит JSON id/name, а не служебное __type__. Исследуемые 78 исходников и эталонные рёбра не менялись. Один исправленный тест проходит на обоих ядрах. Это прежняя ограниченная цепочка тел методов с заданной авторизацией/валидацией, не полный HTTP-граф.

На основном входе неизвестные остались в 46/103 шагах; число пар шаг–поле уменьшилось с 137 до 131. Все сценарии partial. Эти счётчики и частоты предупреждений отражают распространение неопределённости, а не точность или число независимых дефектов. Свидетель отсутствующих данных объясняет две неоднозначности, а не остальные технические ограничения. Промежуточные checkpoint-отчёты не используются для метрик.

Семантика сверена через Context7 и первичные материалы: [TypeFactory 2.9](https://fasterxml.github.io/jackson-databind/javadoc/2.9/com/fasterxml/jackson/databind/type/TypeFactory.html), [TypeBindings](https://fasterxml.github.io/jackson-databind/javadoc/2.14/com/fasterxml/jackson/databind/type/TypeBindings.html), [Jackson: настройки десериализации](https://github.com/FasterXML/jackson-databind/wiki/Deserialization-Features). Внешние источники и модели не используются построителем ответа.
