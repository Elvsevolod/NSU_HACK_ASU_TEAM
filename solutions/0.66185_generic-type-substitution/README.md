## Что изменилось

Полные parameterized-superclass и superinterfaces извлекаются из AST, включая параметры интерфейсов и их верхние границы. Текст аннотации не создаёт ложного предка. Аннотированные параметры методов сохраняют свою область имён.

Каждая подстановка JSON-типа сохраняет место использования аргумента и окружающую область. Для унаследованного поля составляется цепочка до класса, объявившего поле. Проверены вложенные Map/List, несколько уровней, перестановка аргументов, одинаковые имена параметров, импорты и raw-bound erasure. Кеш содержит только исходные пути; разные объекты и инстанцирования не делят значения или параметры.

Лишние JSON-свойства не становятся полями Java. Без доказанной политики объект остаётся неизвестным; нативный literal ignoreUnknown=true позволяет отбросить лишние свойства. Комментарии, строки и внешние аннотации не подделывают этот факт. Не создаются произвольные экземпляры абстрактных/внутренних типов; JSON null не превращается в Java primitive-null без предупреждения.

Это ограниченная модель схемы HTTP/JSON. Полные Java-generics, runtime cast, Jackson, JavaBeans и жизненный цикл Spring не заявляются. [Точные границы](DIAGNOSTICS.md), [ревью и проверенные контрпримеры](benchmark/code-review.json).

## Запуск и воспроизводимость

Из каталога варианта, с Python 3.11:

~~~sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PYTHONHASHSEED=0 .venv/bin/python -B code/offline_run.py --source /path/to/project --skeleton /path/to/skeleton.json.gz --context /path/to/context --scenarios /path/to/scenarios --output /tmp/submission.json --report /tmp/analysis-report.json
.venv/bin/python -B code/verify_run.py --submission /tmp/submission.json --report /tmp/analysis-report.json --output /tmp/verification.json
PYTHONPATH=code .venv/bin/python -B -m pytest code/tests -q -p no:cacheprovider
~~~

Для входа этого репозитория: --source ../../tt-challenge/targets/trainticket, --skeleton ../../tt-challenge/skeleton/trainticket.json.gz, --context ../../tt-challenge/context, --scenarios ../../tt-challenge/scenarios. Эталон читает отдельный evaluator после построения. Offline-аудит запрещает сеть, дочерние процессы и чтение эталона. Проверены основания рёбер, другой ID S0 и hash seed. Извлечённый архив дополнительно повторяет все восемь ответов и тесты.
