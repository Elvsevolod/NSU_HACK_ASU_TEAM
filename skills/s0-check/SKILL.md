# Проверка варианта

Локальный вердикт по готовому варианту. Рамка и критерии приёмки — в `solutions_G/docs/hackathon-rules.md` (§7); поля бенчмарка в README — в `solution-versions`. Здесь только порядок проверки.

## Когда применять

- Вариант собран: есть `submission.json` и код. Проверка идёт до аудита и до сборки посылки.
- Не применять к варианту, уже оценённому сайтом: его код и ответ не трогаются.

## Как запускать

Из корня репозитория:

```bash
py -3 skills/s0-check/scripts/check.py \
  --submission solutions_G/—_feature/submission.json \
  --save solutions_G/—_feature/benchmark
```

Структурный рефактор — тем же скриптом, со сверкой с родителем:

```bash
py -3 skills/s0-check/scripts/check.py \
  --submission solutions_G/—_refactor/submission.json \
  --parent solutions/0.909870_field-constructor-projection \
  --require-identical --tests \
  --save solutions_G/—_refactor/benchmark
```

Ключи: `--parent` — папка родительского варианта (сверка ответов и отдельный S0 родителя), `--require-identical` — расхождение с родителем считать провалом, `--tests` — pytest варианта (`code/tests`, нужен `pytest==9.1.1`), `--save` — куда сохранить отчёты, `--challenge` — путь к пакету организаторов, если он не найден вверх по дереву, `--python` — интерпретатор для дочерних запусков (по умолчанию — из `.venv` варианта, если оно создано, иначе текущий).

Скрипт сам выставляет дочерним процессам `PYTHONUTF8=1`, `PYTHONHASHSEED=0`, `PYTHONDONTWRITEBYTECODE=1`.

## Что проверяется

| Проверка | Источник |
| --- | --- |
| S0 по открытому эталону | официальный оценщик `tt-challenge/platform/evaluate_golden.py` |
| S0 родителя и дельта | он же, по ответу родителя |
| Формат S0–S7 | он же в режиме `--check` по скелету |
| Совпадение с родителем | SHA-256 сырых байтов и с LF-нормализацией |
| Тесты варианта | `pytest code/tests` с `PYTHONPATH=code` |

## Как читать результат

- **Балл S0** — по открытому сценарию; показатель узкий (принцип 7 правил): ловит поломку, роста от него не ждём. Числа по видам связи — там же, где балл.
- **Отклонённые рёбра формата** — ошибка: такие рёбра не считаются. Разбирай причины по строкам отчёта.
- **Сверка с родителем** — для структурного варианта ответ обязан совпадать байт-в-байт (расхождение только в переводах строк — те же данные); для изменяющего ответ сверка информационная, ответ обязан отличаться.
- **Дельта S0 и виды связи родителя** — в отчёте, не сверяй их глазами по README.

## Решение по результату

- **Структурный рефактор**: `--require-identical` без провалов, формат без отклонений, тесты зелёные.
- **Изменяющий ответ**: формат без отклонений, тесты зелёные, S0 зафиксирован вместе с дельтой. Рост S0 не доказывает улучшение на скрытых сценариях.
- **Корневой вариант**: сверять не с чем — S0, формат, тесты.
- Регресс или поломка — разбирайся, а не списывай; если вариант всё равно идёт дальше, зафиксируй регресс в README.

## Что сохраняет `--save`

`evaluation.json` (отчёт S0), `format_check.json` (отчёт формата), `comparison.json` (сверка с родителем — при `--parent`). Отсюда берутся числа для README: полные значения — в JSON, округлённые — в README. SHA-256 ответа печатает сам отчёт.

## Границы

- Скрытые S1–S7 локально проверяются только по формату; оценка по существу — на сайте.
- Проверка не судит законность изменения: поведение по ID сценариев, готовые рёбра и прочие запреты правил — предмет отдельного аудита.
- Коды выхода: 0 — проверки пройдены, 1 — не пройдены, 2 — проверка не выполнялась.
