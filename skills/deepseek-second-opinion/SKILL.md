# Идеи DeepSeek для анализа задачи

**Ты, Codex, ведёшь анализ и принимаешь решения.** Привлекай DeepSeek как источник возможных идей: спрашивай его варианты, разбирай их и используй те, которые выдержали проверку. Его уверенность, согласие с тобой и подробность ответа сами по себе ничего не доказывают.

## Когда обращаться

Самостоятельно подключай DeepSeek при выборе алгоритма или архитектуры, поиске причин ошибки, разборе неоднозначных результатов, сравнении компромиссов или когда текущие гипотезы перестали давать прогресс. Не жди отдельного напоминания пользователя.

Возвращайся за новым мнением при существенных новых данных, неожиданном результате проверки или смене постановки задачи. Периодичность определяется ходом анализа: не спрашивай его на каждом шаге и не повторяй один и тот же вопрос без нового контекста. Для очевидного локального решения отдельная консультация необязательна.

## Подготовка консультации

Сначала прочитай постановку, применимые AGENTS.md и релевантные материалы. Кратко зафиксируй известные факты, критерии успеха, главные неизвестные и собственную рабочую гипотезу. Это позволит затем сопоставить предложения с исходной задачей.

Передай DeepSeek необходимый контекст: цель, ограничения, фактические наблюдения, текущий подход и конкретный вопрос. Если просишь независимые варианты, не навязывай предпочтительный ответ формулировкой. Разделяй измеренные результаты и предположения; не передавай лишние файлы или секреты.

Попроси несколько содержательно разных подходов, если они есть. Для полезной идеи нужны объяснение механизма, условия применимости, ограничения и способ дешёвой проверки. Попроси также возражения к текущему подходу и самый простой вариант решения. Не требуй искусственного разнообразия, когда задачу естественно решает один подход.

Пример поручения, который нужно адаптировать к задаче:

> Проанализируй описанную задачу и предложи альтернативные подходы. Для каждого объясни, почему он может помочь, какие предположения нужны, где он может не сработать и какой небольшой эксперимент различит варианты. Отдельно укажи слабые места текущего подхода. Ожидаемый эффект обозначай как гипотезу; не придумывай замеры. Дай предложения текстом, файлы не меняй и к реализации не приступай.

## Запуск OpenCode для консультации

Используй установленный `~/.local/bin/opencode-deepseek`, только модель `opencode/deepseek-v4.1-flash-free` и рассуждение `max`, в том числе для служебных обращений. При недоступности сервиса сообщи об этом и продолжай доступный собственный анализ; модель не заменяй.

Запускай из абсолютного каталога проекта. Передавай поручение отдельным аргументом процесса без `shell=True`. Для этой консультации запрети изменения, shell-команды и запуск других исполнителей через разрешения только текущего процесса:

```python
from pathlib import Path
import json
import os

env = os.environ.copy()
env["OPENCODE_PERMISSION"] = json.dumps({
    "edit": "deny",
    "bash": "deny",
    "task": "deny",
    "external_directory": "deny",
})
args = [
    str(Path.home() / ".local/bin/opencode-deepseek"),
    "run", "--dir", str(project_dir),
    "--format", "json", "--agent", "build", "--variant", "max",
    consultation_text,
]
```

Здесь `project_dir` и `consultation_text` задаются по текущей задаче; передай `env` в вызов `subprocess`. Нативные инструменты чтения позволяют исследовать нужные файлы проекта. Если проверка требует выполнения команды, выполни её сам в рамках разрешённой задачи. Не ослабляй ограничения ради ответа консультанта.

Сохраняй stdout непосредственно в файл JSONL, stderr отдельно, за пределами кода варианта решения. Прочитай текст ответа и события ошибок; одного успешного завершения процесса недостаточно. Сохрани `sessionID`: уточнения по той же гипотезе передавай через `--session SESSION_ID` и тот же `--dir`. Для нового независимого взгляда создай отдельную сессию. Следи за длительностью запуска; при зависании останови процесс, а при повторном отсутствии прогресса заверши консультацию.

В OpenCode уже подключены глобальный AGENTS.md и полный Karpathy Guidelines. Эти правила действуют и при консультации. Для сомнительных API и библиотек проверяй документацию через Context7; в публичный поиск gh_grep не передавай приватный код и данные проекта.

## Самостоятельная оценка со стороны Codex

Разбери содержательные предложения, включая те, с которыми первоначально не согласен. Для каждого существенного варианта определи:

- какую проблему он решает и за счёт какого механизма;
- подтверждены ли исходные предположения исходниками, документацией или наблюдениями;
- соблюдает ли он ограничения задачи и чем отличается от уже проверенного;
- какой ожидается выигрыш, какова сложность и какие возможны ухудшения;
- какой минимальный эксперимент или контрпример позволит его принять либо отклонить.

Проверяй проверяемое сам: читай указанные участки кода, сверяй API с актуальной документацией, воспроизводи пример, сравнивай с исходным подходом на релевантных данных. Соразмеряй глубину проверки с последствиями решения. Непроверенные идеи называй гипотезами; не выдавай обещанный прирост за измеренный результат.

Уточняй у DeepSeek конкретные пробелы и противоречия, когда это помогает следующему решению. Не превращай обсуждение в бесконечный обмен мнениями и не принимай вариант только из-за согласия двух моделей. Выбирай по доказательствам и критериям задачи. Полезную часть идеи можно объединить с собственным подходом.

## Применение в NSU_HACK_ASU_TEAM

Соблюдай проектный AGENTS.md: консультация предназначена для разработки анализаторов; готовое решение остаётся на Python без внешних LLM API. `tt-challenge/`, `sample/` и прежние `runs/` доступны только для чтения; Train Ticket и его сервисы не запускай. Эталон используй для проверки, а не построения ответа; не добавляй поведение по идентификаторам S0–S7.

Перед созданием варианта или фиксацией бенчмарка прочитай [solution-versions](../solution-versions/SKILL.md). Сравнивай только реальные измерения и сохраняй различие между локальным S0 и оценкой сайта. Предложение DeepSeek само по себе не является основанием менять оценённый вариант.

Если выбранная идея требует реализации, продолжи работу в рамках задания пользователя. Для передачи кода DeepSeek используй [deepseek-delegation](../deepseek-delegation/SKILL.md): там обязательны твоё собственное код-ревью и независимая проверка результата.

## Результат консультации

Кратко объясни пользователю, какие полезные идеи предложил DeepSeek, что ты проверил, что выбрал или отклонил и почему. Отдели подтверждённые выводы от следующих экспериментов. Приёмка идей и итоговое решение остаются за Codex.
