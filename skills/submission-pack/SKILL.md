# Сборка посылки

Архив собирается из папки готового варианта **после** проверки (`s0-check`) и аудита. Требование организаторов — `sample/README.md`: обычный zip с кодом и `submission.json` в корне. Здесь — как собираем мы.

## Когда применять

- Вариант прошёл проверку; пользователь дал отдельное поручение собирать посылку.
- Уже отправленный архив не пересобирается: изменился ответ — это новый вариант (`solution-versions`).

## Состав архива

| Что | Зачем |
| --- | --- |
| `submission.json` в корне | обязательный файл посылки |
| `code/` | код решения: организаторы перезапускают код лучших решений |
| `requirements.txt` | окружение для запуска |
| `README.md` | инструкция запуска, бенчмарк, хеши |
| `benchmark/` | сохранённые отчёты проверок — как в решениях № 1–5 |

В архив не попадают служебные каталоги (`.venv/`, `__pycache__/`, `.pytest_cache/`), файлы ОС (`.DS_Store`, `Thumbs.db`), байткод (`*.pyc`) и вложенные архивы (`*.zip`). Исключения ведёт скрипт: они действуют на любом уровне вложенности. Сам акт `benchmark/pack.json` тоже не попадает внутрь — он складывается после сборки архива.

## Как собирать

Из корня репозитория:

```bash
py -3 skills/submission-pack/scripts/pack.py --variant solutions_G/—_feature
```

Архив ложится в `<вариант>/solution.zip`. Существующий файл не перезаписывается без `--force`; `--out` задаёт другой путь. Если пакет организаторов не найден вверх по дереву, укажи `--challenge`.

## Что проверяет скрипт

- `submission.json` лежит в корне архива и читается как JSON;
- ответ из архива совпадает с ответом на диске по SHA-256;
- официальная проверка формата идёт по копии **из архива** — отклонённых рёбер нет;
- ответ есть на все сценарии задания (`tt-challenge/scenarios/`, S0–S7);
- в архиве нет служебного мусора.

Это проверка посылки. Поведение и качество самого варианта проверяет `s0-check` — не путать.

## Акт и хеши

`benchmark/pack.json`: дата, хеши архива и ответа (сырые байты и LF), размер, список файлов, окружение, итог формата. Хеш ответа сверяется с записью в README варианта; хеш архива указывается в `benchmark/site-score.json` при внесении оценки сайта (порядок — в `solution-versions`).

## После сборки

- Загрузка на платформу — отдельным поручением пользователя.
- Оценка сайта приходит скриншотом; запись — по `solution-versions`.
